# AI Radar 브리프 서식 (표준)

2026-09-09 제정. 사용자가 GPT-6 Astra 분석 화면판(`outputs/openai-gpt-6-astra.html`)을
표준으로 지정했다. **정본은 `docs/brief-template.html`의 `<style>`** 이고, 이 문서는 그
서식을 언제 어떻게 쓰는지 적는다. 둘 중 하나만 고치지 않는다.

같은 계열의 형제 서식이 `outputs/insight-report/*.html`(월간 Insight 리포트)이다. 토큰·활자가
같고, Insight는 "한 사람이 한 번 읽고 판단하는" 흐름형, 브리프는 "여러 사람이 찾아 읽는"
참조형이라 구조가 다르다. 자료·근거를 표와 목록으로 세우는 문서는 브리프, 판단을 요청하는
문서는 Insight.

## 언제 쓰나

- `wiki/analysis/` 페이지처럼 **근거가 많은 참조 문서를 팀에 공유**할 때
- 모델·도구 평가 종합, 사례 비교, 타임라인이 있는 정리, 리서치 결과 보고
- 산출물은 `outputs/<slug>.html`(화면판, 아티팩트 발행) + `outputs/<slug>.pdf`(화면 그대로 인쇄)

## 토큰

| 이름 | 값 | 역할 |
|---|---|---|
| `--paper` | `#ffffff` | 종이. 단일 테마(라이트) — 인쇄물 계열이라 다크 모드를 두지 않는다 |
| `--ink` | `#191919` | 본문·제목·굵은 상단선 |
| `--red` | `#e63329` | **한 문서에 한 역할군만**: 제목 강조어 1개, 섹션 태그, 날짜, 상충·경고, ▼불만 |
| `--soft` | `#5f5f5f` | 보조 문장(데크·범위·표 라벨) |
| `--faint` | `#9a9a9a` | 메타(날짜·출처 라벨·출처 시각) |
| `--hair` | `#e2e2e2` | 헤어라인 구분선 |
| `--wash` | `#f7f7f6` | 부록·경고 띠 배경 |
| `#fffafa` | — | 상충 박스 배경(빨간 테두리와 세트) |

빨강은 강조가 아니라 **의미 표시**다. 예쁘라고 쓰지 않는다. 한 화면에 빨강이 셋 이상 보이면
하나를 검정으로 돌린다.

## 활자

| 역할 | 서체 | 크기 · 행간 |
|---|---|---|
| 제목 h1 | Noto Serif KR 700 | 42px · 1.3 (모바일 33px) |
| 데크 | Noto Serif KR 500, `--soft` | 21px · 1.65 |
| 섹션 h2 | Noto Serif KR 700 | 27px · 1.4 |
| 소제목 h3 | Noto Serif KR 600 | 21px · 1.5 |
| 본문 | IBM Plex Sans KR / Pretendard 400 | 18px · 1.9 · 자간 -.2px |
| 근거 목록 | 본문 서체 | 16.5px · 1.85 |
| 표 | 본문 서체 | 14.5px · 1.7, 숫자 `tabular-nums` |
| 라벨·태그·날짜 | IBM Plex Mono 500, 대문자, 자간 .12~.16em | 10.5~12px |

Google Fonts 한 줄로 세 가족을 받는다(템플릿 2행). 아티팩트 CSP가 허용하는 유일한 외부
스타일 출처라 다른 폰트 호스트는 쓸 수 없다.

## 레이아웃

- **글 폭 580px**, 가운데. 본문 한 줄 33자 안팎 — Insight와 같은 리듬.
- **표만 좌우 56px bleed**(`.tbl`). 숫자가 눌리지 않게 본문 폭 밖으로 낸다. 760px 이하에서는
  bleed를 접고 가로 스크롤.
- 문단 간격 36px(`--gap`), 섹션 간격 `--gap × 2.4`, 부록·출처 앞 `--gap × 2.4`.
- 상단선 위계: 머리·섹션·출처는 **3px 검정**, 표 상단은 1px 검정, 행 구분은 헤어라인,
  표 마지막 행은 다시 1px 검정으로 닫는다.
- 모바일(640px 이하): 본문 17px, 좌우 20px, 제목 33px. 결론 블록의 2열은 1열로.

## 구성요소

| 블록 | 클래스 | 언제 | 규칙 |
|---|---|---|---|
| 머리 | `.mast` `h1` `.dek` `.scope` `.nav` | 항상 | 제목 강조어는 `span.r` 하나. 데크는 결론 한 문장. 내비는 섹션 id로 |
| 결론 블록 | `.verdict > .v` + `.lab.up/.split/.down` | 결론이 2~4갈래로 갈릴 때 | 라벨 색이 곧 방향(검정 호평 · 회색 양분 · 빨강 불만). 갈래마다 굵은 한 줄 + 근거 한두 문장 |
| 섹션 머리 | `.sec-head` + `.tag` + `h2` | 모든 섹션 | 태그는 섹션의 성격 한 단어(전제·지도·호평·양분·불만·비교·검증·방법·유보) |
| 표 | `.tbl > table`, `td.k` 라벨, `td.d` 날짜, `.dir` 방향, `.src-cell` 출처 | 비교·사양·타임라인 | 방향 표시 ▲▼◆는 실제 방향이 있을 때만. 날짜는 실제 순서일 때만 |
| 근거 목록 | `ul.ev > li` + `.who` `.fig` `.cite` | 경험담·측정 나열 | **한 항목 = 한 사람·한 측정.** 앞에 출처 라벨, 끝에 원문 링크, 수치는 `.fig` |
| 읽는 법 | `.caveat` | 숫자 표 앞 | 벤더 발표·표본 편향처럼 숫자를 어떻게 봐야 하는지 |
| 순서 목록 | `ol.how` | 실제 단계·순서가 있을 때만 | 번호 원은 순서가 정보일 때만 쓴다 |
| 요점 목록 | `ul.plain` | 시사점·유보 | `<b>`로 요점 첫 구절 |
| 상충 기록 | `.clash` | 위키 상충이 있을 때 | 빨간 테두리·연분홍 배경. 무엇이 충돌하고 무엇을 우선했는지 |
| 부록 | `.appendix` | 본문에서 내린 사양·타임라인 | 회색 워시, 상단선 없음, h2는 회색 22px |
| 출처 | `.foot` `h4` `ul.srcs` `.when` `.colophon` | 항상 | 소그룹(실측·인상·커뮤니티·벤치마크)으로 나눈다. 콜로폰에 원본 md 경로와 개정 이력 |

## 쓰는 절차

1. 원본은 마크다운(`wiki/analysis/<slug>.md`)에 먼저 쓴다. 화면판은 그 표현이다.
2. `docs/brief-template.html`을 `outputs/<slug>.html`로 복사해 `{{ }}`를 채운다.
   안 쓰는 블록은 지운다.
3. 렌더 확인은 한 번. 브라우저로 열어 머리·표·상충 블록만 본다.
4. 아티팩트 발행: `Artifact(file_path)` — 처음이면 favicon, 갱신이면 같은 경로로 재발행.
5. PDF: `node scripts/build-brief-pdf.mjs outputs/<slug>.html` → 같은 이름 `.pdf`.
   **화면 그대로** 찍는다(재조판 없음). 마지막 쪽이 거의 비면 화면판 분량을 손본다.
6. 원본 md 머리 인용 블록에 화면판·아티팩트·PDF 경로를 적고, `index.md`·`log.md` 갱신, 커밋.

## 지키는 것

- 한 문서에 빨강 강조어는 제목에 하나. 나머지 빨강은 전부 의미 표시.
- 구조 표시(번호·▲▼◆·날짜 열)는 내용이 실제로 그 구조일 때만.
- 근거마다 원문 링크. 링크 없는 수치는 싣지 않거나 `[추정]`.
- 편향·한계는 앞(수집 범위 표)에, 유보는 뒤(확인하지 못한 것)에 — 숨기지 않는다.
- `<!DOCTYPE>`·`<html>`·`<head>`·`<body>`를 쓰지 않는다(아티팩트 래핑 규약).
