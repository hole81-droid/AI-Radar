# AI Radar 웹 전면 재설계 — 설계 스펙

날짜: 2026-07-09
상태: 사용자 승인 완료 (구현 전)

## 1. 배경과 목표

현재 웹(web/)은 "채팅이 홈, 뉴스레터는 마크다운 원문 렌더" 구조이며 스타벅스 디자인
시스템이 임시 적용된 상태다. 사용자 평가: 전반적 UX 불만족 — 채팅 UX(입력창 상단·답변
하단 누적), 뉴스레터 탐색·가독성, 비주얼 전반.

**목표**: "매일 발행되는 큐레이션 뉴스 미디어 + 그 위에서의 대화"라는 제품 본질에 맞게
구조·UX·비주얼을 재설계하고, PRD/DESIGN/CLAUDE 문서 체계를 갖춘다.

## 2. 사용자와 핵심 job

- 사용자: 팀 구성원(비개발자 포함), 공유 암호로 로그인.
- 1순위 job은 **반반**: ① 오늘의 뉴스레터 읽기 ② 궁금한 것 질문하기.
  → 읽다가 그 자리에서 질문하는 **통합 경험**이 설계의 중심축.

## 3. 정보 구조 (승인: 구조 1안)

```
/               오늘의 이슈 — 최신 뉴스레터를 매거진 프론트페이지로 렌더 (홈)
/issues         아카이브 — 호별 카드 목록 (NO. · 날짜 · 헤드라인 미리보기 · 섹션별 건수)
/issues/[date]  과거 호 — 홈과 동일한 매거진 레이아웃
/chat           전용 대화 — 표준 채팅 UX 풀스크린, 히스토리 저장
/cases          케이스 라이브러리 — 필터 탐색 (기능 유지, 재스타일)
/wiki, /wiki/[slug]  위키 카탈로그 + 아티클 뷰 (가독성 개선)
/agent          Agent 연동 안내 (재스타일만)
/login          로그인 (재스타일만)
```

- 기존 `/newsletter/*` URL은 `/issues/*`로 리다이렉트.
- 뉴스레터는 **"호(Issue) — NO. n"**으로 브랜딩. 호수는 발행일 오름차순 순번.

### 글로벌 요소

- **마스트헤드**: `AI RADAR` 워드마크 + 날짜/호수 + 섹션 네비(이슈 · 아카이브 · 케이스 ·
  위키 · 대화) + "질문 ↗" 버튼. 신문 1면처럼 괘선 마감.
- **채팅 슬라이드 패널**: 모든 페이지에서 "질문 ↗" 버튼(단축키 `/`)으로 우측 ~420px
  오버레이 패널. ESC/바깥 클릭으로 닫힘. `/chat`과 동일한 대화 저장소 공유, 패널 헤더에
  "크게 보기 → /chat" 링크.

## 4. 홈 = 오늘의 이슈 (매거진 프론트페이지)

레이아웃 순서:

1. 마스트헤드
2. 호 스트립: `NO. n`(레드) + 날짜·요일 + "데일리 브리핑"
3. 리드 스토리: "오늘의 헤드라인" 섹션을 리드 헤드라인(타이포 스케일은 7절: 데스크톱
   28~34px) + 요약 문단으로
4. 번호 섹션: `01 에이전트 구축 · 업무 자동화` → `02 빅 뉴스` → `03 커뮤니티 화제` →
   `04 YouTube 픽` (뉴스레터에 존재하는 섹션만, 순서 유지). **"★ 최우선" 배지는 표시하지
   않는다** (2026-07-09 사용자 지정).
5. AX 시사점: 레드 좌측 보더의 인용 박스
6. 푸터 네비: ← 이전 호 / 아카이브 전체 보기

### 항목 렌더링

- **01 에이전트 섹션 항목**: 구조화 카드 — 제목, 한 줄 개요, 도구/자동화 업무/방법
  서브필드 표(포인트는 개요에 병합 가능), 하단 액션 행.
- **02~04 섹션 항목**: 컴팩트 리스트 — 제목 + 한 줄 요약, 컬럼 그리드(데스크톱 2~3열,
  모바일 1열).
- **모든 항목의 세 출구**: ① 원문 출처 링크 ② 관련 위키 링크(빌드 시 제목 매칭, 없으면
  생략) ③ **"더 알아보기 ↗"** — 항목 컨텍스트를 안고 채팅 패널 열림.
- 관리용 체크박스(`- [ ]`)는 웹에서 숨긴다.

### 파싱 전략

- `web/scripts/build-content.mjs` 확장: 뉴스레터 마크다운을 섹션(h2)·항목(리스트)·
  서브필드(도구/자동화한 업무/방법/포인트) 단위로 구조화한 JSON 생성.
- 템플릿과 안 맞는 호는 구조화 필드를 비우고 **마크다운 폴백** 렌더.
- 항목↔위키 매칭: 빌드 시 항목 제목·출처 URL을 위키 페이지 제목/source와 퍼지 매칭.

## 5. 채팅 UX

### 전용 /chat 페이지 (표준 채팅 문법)

- 메시지 시간순 위→아래, 최신이 아래. **입력창 하단 고정(sticky)**, 자동 스크롤 추종.
- **SSE 스트리밍**: `/api/qa`를 스트리밍 응답으로 개편, 토큰 단위 실시간 표시.
- **마크다운 렌더링**: 답변에 react-markdown 적용 (볼드·목록·표).
- **근거 칩**: 답변 하단에 번호 칩(출처명) → 위키 페이지/이슈로 이동.
- **멀티턴**: 이전 메시지 배열을 API에 전달, 이어지는 질문 지원.
- **저장**: localStorage. 새로고침 유지, "새 대화" 시 이전 대화는 "최근 대화" 목록에
  보관·재열람. 서버 저장은 하지 않는다(팀 공유 계정이라 개인 구분 불가).
- 빈 상태: 제안 질문 (고정 4개 + 가능하면 오늘 이슈 항목 기반).

### 슬라이드 패널

- /chat과 동일 컴포넌트·저장소의 컴팩트 뷰.
- "더 알아보기 ↗" 클릭 → 패널 열림 + `[NO. n · 섹션] '항목 제목' 항목 더 자세히 알려줘`
  형식의 질문 **자동 전송**.

### API 변경

- `POST /api/qa`: `{ messages: [{role, content}...] }` 수신, SSE 스트림 응답
  (`text` 델타 → 종료 시 `sources` 메타). 기존 단건 `{question}` 하위호환 유지.

## 6. 나머지 페이지

- `/issues`: 호 카드 그리드 — NO., 날짜, 리드 헤드라인, 섹션별 건수. 최신순.
- `/cases`: 필터(업무 영역·도구·방식) 유지. 칩 → 각진 사각 태그, 카드 → 괘선 기반.
  "실운영" 골드 배지 등 스타벅스 요소 제거, B1 문법(레드 포인트)으로.
- `/wiki/[slug]`: 아티클 뷰 — 본문 폭 680px, 제목 위계 정돈, 상단 메타 스트립(타입·날짜·
  중요도·원문 링크). `/wiki` 카탈로그는 index.md 렌더 유지 + 타이포 개선.
- `/agent`, `/login`: B1 재스타일만.

## 7. 디자인 시스템 — B1 "인터내셔널" (승인)

참조 계보: Monocle·신문 국제판. 흑백 + 레드.

### 토큰

| 역할 | 값 |
|---|---|
| 종이(캔버스) | `#ffffff` |
| 잉크(제목·강조) | `#111111` |
| 레드(포인트) | `#e63329` |
| 본문 텍스트 | `#333333` |
| 보조 텍스트 | `#555555` / `#888888` |
| 헤어라인 | `#e5e5e5` |
| 옅은 면 | `#f7f7f7` |

- **레드 사용 규칙**: 섹션 번호, 액티브 상태, 프라이머리 액션만. 장식 금지.
- **다크모드 없음** — 종이 컨셉 고정.

### 타이포

- Pretendard 계열 산세리프 단일 체계.
- 헤드라인: 500~700, `-0.02em`. 리드 헤드라인 28~34px(데스크톱).
- 라벨: 10~12px, 대문자 스타일 자간 `.12~.16em`.
- 본문: 16px / 1.7 / `#333`. 날짜·번호 tabular-nums.

### 괘선·형태

- 괘선 위계: 3px 블랙(큰 단락) → 1px 블랙(섹션) → 1px 헤어라인(항목).
- 컨트롤은 각진 사각형(radius 0~2px), 링크는 밑줄. **필 버튼·라운드 카드·그림자 등
  스타벅스 잔재 전면 제거.** 카드가 필요하면 보더 기반 플랫.

## 8. 문서 체계

- `web/PRD.md` — 제품 정의: 사용자, 핵심 job, 페이지별 요구사항, 비범위, 성공 기준.
- `web/DESIGN.md` — 본 스펙 7절의 디자인 시스템 전체 (토큰 표, 컴포넌트 스펙, Do/Don't).
- `web/CLAUDE.md` — 웹 작업 가이드: 디렉토리 구조, 콘텐츠 파이프라인, "UI 작업 전
  PRD.md·DESIGN.md 필독" 규칙.
- 루트 `CLAUDE.md` — web/ 문서 포인터 한 줄 추가 (위키 스키마 본문은 불변).

## 9. 비범위 (이번 재설계에서 하지 않는 것)

- 서버측 대화 저장, 사용자 개인화·개별 계정.
- 뉴스레터 원본(newsletter/*.md) 형식 변경 — 파서가 현재 템플릿에 맞춘다.
- 위키 콘텐츠·스키마 변경, MCP/REST Agent API 변경.
- 다크모드.

## 10. 성공 기준

- 홈에서 오늘의 이슈가 매거진 레이아웃으로 렌더되고, 템플릿 불일치 호는 폴백으로 깨지지
  않게 표시된다.
- 항목의 "더 알아보기"로 패널이 열리고 컨텍스트 질문이 자동 전송·스트리밍 답변된다.
- /chat에서 하단 입력창·자동 스크롤·마크다운 답변·근거 칩·새로고침 후 대화 유지가
  동작한다.
- 전 페이지가 B1 토큰만 사용하며(그린·필 버튼 잔재 0), 로그인 포함 전 화면 일관.
- PRD/DESIGN/CLAUDE 문서가 존재하고 상호 참조가 정확하다.
