# AI Radar 데일리 — 2026-09-19

## 오늘의 헤드라인
Anthropic이 "Claude가 자사 R&D의 26%를 주도한다"는 수치를 처음 공개하며 09-12 감속 촉구를 스스로 실행에 옮긴 한편, 같은 주 IPO 밸류에이션은 $2조로 확정됐다. 코딩 에이전트 쪽에서는 벤치마크 두 건이 겹쳤다 — 모델은 저가·고급 티어링(코드리뷰 정밀도 vs 비용), 하네스는 품질보다 비용을 가른다는 실측. Z.ai의 ZCode가 설정을 꺼도 git 히스토리를 몰래 업로드한다는 사실도 드러났다.

## 업무 적용 Case
- [x] **GPT-5.6 Luna vs GPT-6 Astra, 코드리뷰 자동화 벤치마크 — "$1.20짜리 모델이면 충분할까"** — 공개 저장소 PR 50건에 두 모델을 동일하게 붙여 실제 버그 탐지율·비용·속도를 실측 비교. [Entelligence.ai](https://entelligence.ai/blogs/gpt-5.6-luna-vs-gpt-6-astra-is-a-1.20-model-good-enough-for-code-review) → [[entelligence-gpt56-luna-vs-gpt6-astra-code-review-benchmark]]
    - **도구**: GPT-6 Astra·GPT-5.6 Luna(둘 다 OpenAI) + 자체 평가 하네스
    - **자동화한 업무**: PR(pull request) 코드리뷰 — Sentry·Discourse·Keycloak·Cal.com·Grafana 등 실제 공개 저장소 대상
    - **방법**: 동일 PR 세트·동일 프롬프트를 두 모델에 투입 → 사람이 지적된 버그를 실제 버그인지 검증(정밀도 산출) → 정확성/보안 버그로 분류해 카테고리별 집계
    - **포인트**: Astra가 버그 33% 더 발견(92 vs 69건)·정밀도 96%(Luna 74%)·보안버그 2배 이상 더 찾음, 반면 Luna는 비용 28배 저렴($0.20 vs $5.66 총액). "일반 정확성 버그는 저가 모델로 충분, 인증·권한 코드는 상위 모델로" 라는 모델 티어링 원칙의 실측 근거.

## AX 시사점
오늘 묶이는 세 갈래 뉴스를 함께 읽으면 "AI 벤더가 스스로 밝히는 숫자"와 "제3자가 독립적으로 실측한 숫자"를 구분해야 한다는 그림이 뚜렷해진다. Anthropic의 "26% 자기주도 R&D"는 회사 자체 보고(검증되지 않음)인 반면, HarnessTax·GPT-5.6 Luna/Astra 벤치마크는 제3자가 재현 가능한 방법론으로 실측한 결과다. 기업이 AI 에이전트 도입을 검토할 때도 같은 원칙이 적용된다 — 벤더의 ROI 주장을 그대로 받기보다, McKinsey가 지적하듯 "어디서 인계(handoff)가 막히는가"를 먼저 진단하고, HarnessTax처럼 같은 모델을 여러 하네스에서 직접 비교하는 절차를 자체적으로 거치는 편이 안전하다. ZCode 사건은 그 진단에 "데이터가 실제로 어디로 가는가"까지 포함해야 한다는 경고이기도 하다.
