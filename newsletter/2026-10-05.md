# AI Radar 데일리 — 2026-10-05

## 오늘의 헤드라인
Anthropic이 IPO 일정을 구체화했다 — 10월 14일 투자자 데이, 11월 9일 주 공식 마케팅, 추수감사절 전 상장을 목표로 하며 밸류에이션은 $1.8~2조(사상 최대 IPO권)로 거론된다. 같은 시기 Claude Code는 TypeScript로 하네스 자체의 UI·동작을 바꿀 수 있는 "mods" 체계를 정식 출시했다. 업계에서는 Meta를 떠나 월드모델 스타트업을 세운 Yann LeCun이 Anthropic CEO Dario Amodei를 "망상에 빠졌다"고 공개 비판했고, 커뮤니티에서는 "에이전트에게 필요한 건 메모리가 아니라 문서화"라는 주장이 화제를 모았다.

## 업무 적용 Case
- [x] **"에이전트에게 메모리 대신 문서화를 줘라" — 벡터DB 없는 마크다운 기반 지속 기억** — Hacker News 330점을 받은 글(2026-10-03). [출처](https://liao.gg/blog/agents-dont-need-memory)
    - **도구**: 특정 코딩 에이전트에 종속되지 않는 범용 워크플로(Claude Code·Codex 등 적용 가능) + 오픈소스 도구 Operator Memory
    - **자동화한 업무**: 코딩 에이전트의 세션 간 "기억" 관리 — 기존 RAG(벡터 임베딩 유사도 검색) 기반 메모리 플러그인을 구조화된 마크다운 문서 체계로 대체
    - **방법**: 프로젝트 루트의 `internal/` 폴더에 스펙·계획·리서치·결정기록을 평문 마크다운으로 쌓고, "prompt → build → forget"(지시→작업→휘발) 루프를 "prompt → **consult**(문서 열람) → build → **update**(문서 갱신)" 루프로 바꾼다. 임베딩·백그라운드 데몬 없이 전부 읽기·감사·git 커밋이 가능하다.
    - **포인트**: 정량 비교 실험은 없는 한 개발자의 설계 논증(anecdotal)이지만, RAG 메모리의 "유사도로만 호출되지 정확성과 무관함·맥락 손실·조용히 낡음·블랙박스" 같은 구조적 결함 지적은 강의 소재로 바로 쓸 수 있다. 이 위키(AI Radar) 자체가 벡터DB 없이 순수 마크다운으로 운영되는 동일 패턴이라 비교 설명에도 유용하다. → [[liao-agents-documentation-not-memory]]

이 외에 "도구+자동화한 업무+방법" 구조에 맞는 신규 사례는 이번 스캔에서 추가로 확보하지 못했다(평소처럼 수집 비중을 가장 높게 두고 탐색했으나 1건에 그침).

- [x] **Claude Code, "mods" 체계 정식 출시 — TypeScript로 하네스 자체의 UI·동작을 바꾼다** — 09-29 로드맵 인터뷰에서 예고됐던 기능이 v2.1.287(10/1)로 출시됐다. mod는 플러그인 안에 담긴 JS/TypeScript 이벤트 핸들러로, 툴 호출·프롬프트 제출·화면 렌더링 같은 Claude Code 내부 이벤트를 관찰·수정·가로챌 수 있다. Anthropic은 자사의 `/diff` 패널·AGENTS.md 로더·텔레메트리 전송 로직을 전부 mod로 재구현해 공개했고, 위험한 셸 명령의 영향범위를 미리 보여주는 `blast-radius` 등 샘플 mod와 커뮤니티 카탈로그도 함께 나왔다. 다만 mod는 **샌드박싱되지 않고 사용자 전권한으로 실행**된다 — 신뢰하는 출처의 mod만 설치해야 한다는 경고가 공식 문서에 명시돼 있다. [출처](https://code.claude.com/docs/en/plugins/mods/overview)

## AX 시사점
오늘의 묶음은 "AI 1세대 벤더들이 자본시장·플랫폼·여론 세 전선에서 동시에 움직이고 있다"는 그림을 보여준다. IPO 쪽에서는 투자자 데이 날짜가 못박히고 지배구조(창업자 50.1% 의결권 유지)까지 공개되면서 "상장은 성장 자금 조달이지 경영권 매각이 아니다"라는 메시지가 뚜렷해졌다 — 기업 고객 입장에서는 벤더의 자본구조 변화가 제품 우선순위·가격 정책에 미칠 영향을 상장 전부터 모니터링할 근거가 하나 더 생긴 셈이다. 플랫폼 쪽에서는 Claude Code mods가 "에이전트 하네스 자체를 조직이 원하는 대로 바꿀 수 있다"는 가능성을 열었지만, 비샌드박스·전권한 실행이라는 점에서 "누가 mods를 검수·승인할 것인가"라는 새로운 거버넌스 과제를 동시에 던진다 — AGENTS.md 지원 때보다 한 단계 더 신중한 내부 정책이 필요하다. 여론 쪽에서는 LeCun의 공개 비판이 "AI 안전 담론 자체가 산업 포지셔닝의 도구가 될 수 있다"는 회의론을 다시 수면 위로 끌어올렸다 — 벤더의 안전 주장과 산업 경쟁 구도를 분리해서 읽어야 한다는 교훈이다. 마지막으로 "에이전트는 메모리가 아니라 문서화가 필요하다"는 오늘의 Case와 "멀티 에이전트 개선의 핵심은 에이전트를 덜 중요하게 만드는 것"이라는 커뮤니티 체감은 같은 결의 실무 조언이다 — 복잡한 메모리·오케스트레이션 인프라를 먼저 들이기보다, 감사 가능한 문서 체계와 단순한 역할 구조부터 갖추는 것이 에이전트 도입의 기본기라는 점을 다시 확인시킨다.
