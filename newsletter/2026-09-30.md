# AI Radar 데일리 — 2026-09-30

## 오늘의 헤드라인
OpenAI가 연례 DevDay에서 "노트북을 덮어도 계속 일하는" 상시 가동 에이전트 **Dots**와 초저가 모델 **GPT-6.1 Sol**을 동시 공개하며 개인비서형 에이전트 경쟁에 정면으로 뛰어들었다. 같은 시점 Anthropic은 IPO 신고서를 공개해 처음으로 구체적인 손익 수치(매출 $4.6B·순손실 $42B·목표 밸류 $2조+)를 드러냈고, 커뮤니티에서는 순손실 규모에 "상장하면 지금까지의 혜택이 끝날 것"이라는 반응이 나왔다. 한편 AX LABS는 Microsoft Research의 "오케스트레이터 없는 멀티 에이전트" 논문을 Claude Code 에이전트 팀에 바로 붙이는 3단계 구현 가이드로 정리해 눈길을 끌었다.

## 업무 적용 Case
- [x] **AX LABS, Microsoft Research "Agensh" 논문을 Claude Code 멀티 에이전트 팀 가이드로 번역** — 중앙 오케스트레이터 없이 워커가 스스로 작업을 클레임·조율하는 설계를 3~5/8~16/32+ 규모별로 이식하는 방법을 정리. [출처](https://theaxlabs.com/blog/agensh-multi-agent-harness-paper-review)
    - **도구**: Claude Code (에이전트 팀 + hooks)
    - **자동화한 업무**: 여러 코딩 에이전트를 사람 개입 없이 병렬 운영하면서 충돌·중복 작업 방지
    - **방법**: 공유 컨텍스트 보드(append-only, 5개 레코드 타입)를 `board.py` 스크립트로 구현 + `TeammateIdle`(15분 무응답 시 행동 촉구)·`TaskCompleted`(테스트 실패 시 완료 차단) 훅 2종 + 모든 워커에 동일 프롬프트(ID만 다름) 부여.
    - **포인트**: 원 논문 실측(pandoc 재구현 통과율 33.89%→55.06%, 1,024 에이전트)은 Agensh 프레임워크 자체 실험이지 Claude Code 위에서 재현된 수치가 아니다 — 이 구분을 명확히 하고 인용해야 한다. 소규모 팀은 1단계(네이티브 에이전트 팀+보드 스크립트)만으로 충분할 가능성이 높다. 상세는 [[agensh-claude-code-decentralized-multi-agent-harness]].

## AX 시사점
오늘은 "에이전트를 파는 회사의 재무 구조가 처음 공개된 날"이었다. Anthropic의 IPO 신고서는 매출이 7배씩 급증하는 동시에 컴퓨트 지출이 영업비용의 절반을 넘는다는 것을 숫자로 보여줬다 — AI 에이전트 서비스의 원가 구조가 매출 성장 속도만큼 무겁다는 뜻이다. 같은 날 OpenAI는 정반대 방향에서 움직였다: Dots로 상시 가동 에이전트를 상위 요금제에 묶고, GPT-6.1 Sol로 토큰 단가를 낮춰 "더 싸게, 더 많이" 파는 전략을 동시에 폈다. 기업이 에이전트 도입을 검토할 때 참고할 대목은, 벤더의 가격 인하가 지속 가능한지(Anthropic의 손익 구조가 보여주듯 원가 압박은 실재한다)와 그 가격에 상시 가동형 vs 요청 응답형 중 무엇을 사는지를 구분해야 한다는 것이다. 한편 AX LABS의 Agensh 가이드는 "에이전트를 몇 개까지 늘릴 것인가"를 조직 내부에서 판단할 때 쓸 수 있는 실무적 체크리스트(3~5/8~16/32+ 규모별 설계)를 제공한다 — 다만 성과 수치가 원 논문 실험치라는 점은 도입 전 반드시 감안해야 한다.
