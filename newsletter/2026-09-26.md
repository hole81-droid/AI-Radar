# AI Radar 데일리 — 2026-09-26

## 오늘의 헤드라인
Anthropic을 둘러싼 정부 리스크가 하루 만에 원점으로 돌아갔다 — 연방 항소법원이 "국방부의 Anthropic 블랙리스트 지정은 위법"이라던 8월 판결을 뒤집고 지정을 다시 정당화했다. 같은 날 Anthropic은 Akamai와 7년 $11.6B 규모 CPU 클라우드 계약을 맺으며 컴퓨트 지출 총액이 1년 안에 $500B를 넘겼고, IPO를 앞두고 창업자 7인이 결합 의결권 50.1%를 확보하려 한다는 보도도 나왔다. 한편 개발자 커뮤니티에서는 코딩 에이전트 여러 개를 동시에 돌릴 때 생기는 "메모리"와 "충돌" 문제를 직접 해결하려는 오픈소스 도구들이 잇따라 등장했다.

## 업무 적용 Case
- [x] **Claude Code + Higgsfield(MCP)로 "AI 슬롭" 없는 비즈니스 웹사이트 제작** — AI 에이전시 운영자가 자신의 홍보 사이트를 콘셉트부터 리드캡처까지 전 과정 구축. [출처](https://www.youtube.com/watch?v=1P5xtV-Kf0o)
    - **도구**: Claude Code + Claude(Fable 5급) + Higgsfield(MCP) + Mobbin·21st.dev(MCP) + 3.js
    - **자동화한 업무**: 웹사이트 콘셉트·카피·미디어(사진 아웃페인팅→모션클립)·UI 제작 및 리드 캡처 시스템 구축
    - **방법**: Claude Code 세션 안에 여러 MCP 서버를 체이닝 — Higgsfield로 이미지를 와이드스크린 아웃페인팅·모션 클립화하고, Mobbin·21st.dev로 UI 레퍼런스를 소싱해 재해석. 강한 카피와 커스텀 미디어로 "AI가 만든 티"를 지우는 데 집중.
    - **포인트**: 정량 성과(전환율 등)는 확인 안 됨(미확인) — 다만 "MCP로 코딩 도구를 크리에이티브 오케스트레이터로 확장"하는 구조 자체가 강의 소재로 유용하다.
- [x] **L&D 팀이 벤더 도구 대신 Claude Projects·커스텀 GPT로 사내 AI 도구를 자체 제작** — 학습과학×AI 교수설계 연구자 Dr. Philippa Hardman이 여러 기업의 관찰 패턴을 정리. [출처](https://drphilippahardman.substack.com/p/the-ai-tools-that-l-and-d-teams-are)
    - **도구**: Claude Projects, 커스텀 GPT, Google Gemini Gem
    - **자동화한 업무**: 과정 착수 전 문제정의·SME 인터뷰 준비, 역할극·시뮬레이션형 학습 경험, 사내 표준 기반 산출물(영상 스크립트·평가·교정) 제작
    - **방법**: 조직 고유의 교수설계 표준·스타일 가이드를 프롬프트에 직접 내장한 맞춤 봇을 엔지니어링 팀 없이 제작. LMS·번역·자막처럼 범용 기능은 계속 구매 유지.
    - **포인트**: 성과 지표를 "생산량"이 아니라 "의사결정 품질"·"불필요한 과정 제작 예방"으로 재정의한다는 프레임이 핵심 — 우리 조직의 본업(역량육성 방법론)에 정면으로 해당하는 사례지만, 특정 기업명·정량 수치는 없는 관찰글임을 감안해야 한다.
- [x] **오픈소스 "jevmem", Claude Code 세션 간 프로젝트 기억을 자동화** — 외부 채점 API로 대화 중 결정·버그·TODO를 판별해 저장. [출처](https://github.com/Avinash-jetwani/jevmem)
    - **도구**: Claude Code(+Cursor·Codex), TypeSafe AI "Jev" 채점 API
    - **자동화한 업무**: 세션이 바뀌어도 프로젝트 결정·제약조건·버그·할일을 잊지 않도록 자동 기록·회수
    - **방법**: 비밀값 스크러빙 → Jev API로 "결정/규칙/버그/인젝션 여부" 확률 채점 → 임계값 규칙으로 저장 여부 결정 → 한 줄 요약 기록(갱신 시 삭제 대신 "superseded" 표시).
    - **포인트**: 같은 날 r/AI_Agents에 "에이전트 메모리 레이어는 완전히 망가졌다"는 불만 글이 화제가 될 만큼 실제 통증 지점을 겨냥한 시도지만, GitHub 66 stars의 초기 프로토타입이라 정량 성과는 미확인 — "메모리 문제는 아직 미해결 영역"이라는 신호로 읽는 게 정확하다.
- [x] **오픈소스 "Foremerge", 병렬 코딩 에이전트의 "의도 충돌"을 코드 작성 전에 감지** — Git이 못 잡는 시맨틱 충돌을 MCP로 사전 경고. [출처](https://github.com/naw103/foremerge)
    - **도구**: Claude Code·Codex·Cursor(MCP), Rust 바이너리 + SQLite
    - **자동화한 업무**: 여러 에이전트가 동시에 같은 코드베이스를 건드릴 때 생기는 "개별로는 맞지만 같이 있으면 틀린" 변경 사전 탐지
    - **방법**: 에이전트가 수정 대상을 시맨틱 범위(예: `symbol:PaymentService=replace`)로 코드 작성 전에 선언 → Git 공통 디렉터리의 공유 SQLite DB로 다른 worktree의 선언과 비교 → 겹치면 경고(차단은 아님, 최종 판단은 사람).
    - **포인트**: GitHub 507 stars로 화제성은 확인됐지만 제작자 스스로 "공식 벤치마크 결과 아직 없음"이라 명시한 pre-1.0 도구 — 병렬 에이전트 운영을 늘리는 조직이라면 파일럿 단계에서만 참고할 만하다.

## AX 시사점
오늘의 세 가지 Anthropic 뉴스(항소법원 판결 반전·Akamai 인프라 계약·창업자 의결권 확보)는 한 회사가 "규제 리스크·인프라 확장·지배구조 설계"라는 서로 다른 축의 불확실성을 동시에 관리하며 상장을 준비하는 모습을 보여준다. 특히 08-27 승소가 09-25 항소심에서 뒤집힌 사건은, 정부와의 법적 분쟁을 "해결된 리스크"로 성급하게 분류하면 안 된다는 실무적 교훈을 준다 — 판결은 확정되기 전까지 진행형 변수다. 한편 업무 적용 Case 네 건 중 절반(jevmem·Foremerge)이 "에이전트를 여러 개 굴릴 때 생기는 새로운 문제(기억 상실·의도 충돌)를 커뮤니티가 자체적으로 풀려는 시도"라는 점도 눈여겨볼 만하다 — 벤더가 아직 표준 해법을 내놓지 못한 영역이라는 뜻이므로, 병렬 에이전트 운영을 계획하는 기업은 이런 초기 도구에 의존하기보다 자체 거버넌스(승인 게이트·충돌 검토 프로세스)를 함께 설계해야 한다. Hardman의 L&D 도구 자체제작 사례는 우리 조직의 본업과 가장 가까운 시사점을 준다 — "얼마나 많이 만들었는가"가 아니라 "만들지 않기로 한 결정의 질"을 성과로 재정의하는 프레임은 프로그램 기획 시 참고할 만하다.
