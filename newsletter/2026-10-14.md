## 업무 적용 Case
- [x] **Anthropic, Claude 에이전트의 코드 폭증에 대응해 git 대체 소스컨트롤 "Scion" 구축** — 공식 엔지니어링 블로그. [출처](https://www.anthropic.com/engineering/redesigning-source-control)
    - **도구**: Claude(에이전트가 작성하는 자율 코드 생성, cli-pipeline)
    - **자동화한 업무**: 급증한 에이전트 커밋량을 감당하는 소스 컨트롤 인프라 — git은 "오프라인 우선" 전제로 설계돼 있어, 2026년 5월 일일 머지 2,500건 → 9월 30,000건 이상으로 폭증한 "항시 온라인 에이전트" 워크로드를 감당하지 못했다.
    - **방법**: 서버 중심 아키텍처(병합·blame을 서버로 이전) + 체인지셋 기반 저장(락 없는 증분 커밋) + 파생 데이터 분리 + 3단 캐싱(데몬→지역캐시→권위서버, 적중률 99%+)으로 자체 VCS "Scion"을 설계, 7인 팀이 코드량 10배 증가 와중에 5개월 만에 전체 마이그레이션 완료.
    - **포인트**: 인프라 footprint 200배 축소·체크아웃 분→초 단위·CI CPU 용량 25% 확보(모두 실측). 9/14 반영된 CI test-impact 재설계([[anthropic-agentic-coding-ci-test-impact-analysis]])와 짝을 이루는 사례로, "에이전트 도입은 모델 교체가 아니라 인프라 재설계 문제"라는 교훈을 강의·AX 양쪽에 그대로 쓸 수 있다. → [[anthropic-scion-source-control-redesign]]
- [x] **"AGENTS.md·MCP는 점성술" — pre-commit hooks로 에이전트 아키텍처 위반을 커밋 단계에서 차단** — Simon Willison이 인용한 Geoffrey Huntley의 기법. [출처](https://ghuntley.com/agency/)
    - **도구**: 코딩 에이전트(Claude Code 등) + git pre-commit hooks
    - **자동화한 업무**: 에이전트가 사내 관찰성(observability) 라이브러리를 우회해 직접 모듈을 호출하는 등의 아키텍처 위반을 잡아내는 "정리" 업무.
    - **방법**: 스킬 팩(AGENTS.md·MCP)에 기대는 대신, git diff를 검사하는 pre-commit hook이 위반 패턴을 발견하면 커밋을 실패시키고 에이전트에게 교정 프롬프트를 주입한다 — "확률적 튜닝"을 "결정론적 검증"으로 바꾸는 접근.
    - **포인트**: 수치 근거는 약하다(hooks 기법 자체의 전후 비교 수치 없음, "3개 회사 10일 재구현"은 별개의 속도 일화). 다만 이 위키의 다른 자료([[anthropic-skill-authoring-best-practices]])는 스킬 저작을 권장하는 반대 입장이라, 강의에서는 "결정론적 검증 vs 선언적 가이드"의 트레이드오프로 양쪽을 함께 소개하는 게 안전하다. → [[ghuntley-precommit-hooks-agent-architecture-enforcement]]

## AX 시사점
오늘의 공통 주제는 "에이전트 확장의 진짜 비용은 어디에 숨어 있는가"다. Anthropic의
Scion 사례는 에이전트 도입이 모델 교체가 아니라 소스 컨트롤·CI 같은 인프라 계층
전체의 재설계를 요구한다는 것을 가장 극적인 수치(머지 건수 12배, 인프라 200배 축소)로
보여줬다. McKinsey 서베이는 같은 간극을 경영 지표로 확인한다 — 대기업 40%가 에이전트를
"확장 중"이라 답하지만 실제로 EBIT에 5% 이상 기여한다고 답한 곳은 6%뿐이다. 개발
현장에서도 비슷한 반성이 나왔다 — "코드를 쓰는 비용"은 줄었지만 "코드를 이해하고
검증하는 비용"은 그대로거나 오히려 늘었다는 것이다. 세 신호를 합치면, AI 도입의
다음 단계 과제는 "에이전트를 더 많이 쓰는 것"이 아니라 "에이전트가 만들어내는 산출물을
인프라·조직·검증 체계가 흡수할 수 있게 만드는 것"이라는 결론으로 모인다.
