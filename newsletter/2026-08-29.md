# AI Radar 데일리 — 2026-08-29

## 오늘의 헤드라인
미 연방법원이 국방부의 Anthropic "공급망 리스크" 블랙리스트 지정을 위헌·위법으로 판결하며
정부에 전면 철회를 명령했다 — 자율살상무기·대량감시 사용제한을 둘러싼 $200M 계약 분쟁이
발단이었다. 같은 시기 보안 연구자는 Claude Code Auto Mode를 60~80% 확률로 우회하는 공격을
공개했고, Anthropic은 "보안 보장이 아닌 최선노력 기능"이라며 샌드박스 격리를 재차 강조했다.
커뮤니티에서는 "코딩 에이전트가 내 정체성을 죽였다"는 개발자 고백이 사흘째 이어지며 AI
의존 피로감 담론이 계속되고 있다.

## 업무 적용 Case
- [x] **exe.dev — 손코딩 없이 6개월, Claude Code+Codex+Cursor 병렬 에이전트 20개 오케스트레이션** —
  개인 개발자가 "더는 손으로 코드를 쓰지 않는다"는 규칙 아래 실제 업무 개발 전체를 에이전트에
  위임한 6개월 기록. [출처](https://blog.exe.dev/engineering-with-ai)
    - **도구**: Claude Code·Codex·Cursor 병행(모델은 GPT-5.3·Opus 4.6 언급), 자체 개발
      오케스트레이터 `botd`
    - **자동화한 업무**: 코드 작성뿐 아니라 테스트 실행·CI 트리거·앱 구동·스크린샷 캡처까지
      개발 워크플로 전체
    - **방법**: 에이전트마다 독립된 exe.dev VM(셸 접근권)을 배정해 파일 충돌·자원 경합을
      원천 차단, `botd`가 VM 프로비저닝·진행상황 추적·대화 히스토리 보존을 담당. 외부 연동은
      읽기전용 우선, 자격증명은 VM에 저장하지 않고 프록시로 경유해 처리. 피크 시 동시 20개
      VM을 병렬 운영
    - **포인트**: 정량 생산성 지표는 없고 "경력 중 최고 생산성"이라는 자기 평가뿐이라 그대로
      도입 근거로 쓰기는 어렵다. 다만 "승인 프롬프트를 느슨하게 풀어 자율성을 얻는" Auto
      Mode류 접근과 달리 "VM 격리로 애초에 승인이 불필요한 구조를 만드는" 접근이라는 점에서,
      바로 아래 Auto Mode 우회 사례와 나란히 놓고 두 자율성 설계 철학의 리스크 차이를
      설명하는 강의 소재로 유용하다.

## AX 시사점
오늘은 "AI 기업과 정부·보안 연구자 사이의 힘겨루기"가 두드러진 날이다. Anthropic이 정부
계약에서 자율살상무기·대량감시 사용제한을 관철하려다 법정까지 갔다가 승소한 사례는, AI
벤더의 사용정책(usage policy)이 단순한 마케팅 문구가 아니라 실제 계약 협상력을 가진
법적 쟁점이 될 수 있음을 보여준다 — 공공부문 AI 도입을 검토하는 조직이라면 계약서의 사용
제한 조항을 가볍게 넘기지 말아야 한다는 시사점이다. 동시에 Claude Code Auto Mode
우회 사례는 "느슨한 승인 완화"의 한계를 보여주는 반면, 오늘 소개한 exe.dev 사례는 VM
격리로 애초에 승인 자체를 불필요하게 만드는 대안적 설계를 보여준다 — 에이전트 자율성을
확대하려는 조직이라면 "분류기 기반 승인 완화"와 "인프라 격리" 중 어느 쪽을 신뢰 경계로
삼을지 명확히 정해야 한다. 한편 사흘째 이어지는 "AI가 내 정체성/뇌/실력을 죽였다"는
개발자들의 고백은, 생산성 지표 뒤에서 실무자들의 스킬 공동화 우려가 결코 일시적 화제가
아니라 지속적인 정서적 저항임을 보여준다 — 도입 속도만큼 숙련도 유지·재교육 설계도
조직의 AX 로드맵에 함께 담아야 한다.
