# AI Radar 데일리 — 2026-10-09

## 오늘의 헤드라인
CrowdStrike는 지난 2주간 한국 은행 9곳을 턴 해킹(6.8만 건 유출)에 공격자가 Claude Code 등 AI 에이전트를 동원했을 가능성이 높다고 공개했다. 같은 주 Anthropic은 보안 프로그램 "Cyber Mission"을 출범하고 사용정책을 11/12부터 개정하며, Barclays는 Claude를 직원 1.6만 명·일일 이메일 12만 건 처리 규모로 전사 확장했다고 밝혔다. 커뮤니티에서는 Claude 사용량을 60% 줄인 캐시 관리 기법과 소형 모델 4종 실측 비교가 화제다.

## 업무 적용 Case
- [x] **Claude Code 서브에이전트, 하트비트 핑+자동 핸드오프로 주간 사용한도 소진 60%↓** — 테라바이트급 데이터를 상시 처리하는 개인 프로젝트에서, 09-17에 알려진 "캐시 TTL 5분→1시간" 기법을 한 단계 더 발전시킨 사례. [출처](https://www.reddit.com/r/ClaudeAI/comments/1x0as2l/subagent_for_long_running_tasks_saved_me_60/)
    - **도구**: Claude Code(서브에이전트 다수, 각자 git worktree에서 장시간 작업 수행)
    - **자동화한 업무**: 장시간(5분~수시간) 서브에이전트 작업의 프롬프트 캐시 비용·주간 사용한도 소진 최적화
    - **방법**: 1시간 캐시 TTL 설정 + 약 45분 주기 하트비트 핑으로 1시간을 넘는 도구 호출에도 캐시를 계속 "warm"하게 유지, 약 175K 토큰 지점에서 서브에이전트가 핸드오프 문서를 쓰고 종료 → 새 서브에이전트가 이어받아 컨텍스트 재적재 자체를 줄임.
    - **포인트**: 토큰 수 자체는 줄지 않고(오히려 소폭 증가) 과금되는 방식만 바뀐다고 작성자가 직접 명시 — "비용 절감"이 아니라 "한도 소진 속도 조절" 기법임을 가르칠 때 구분해야 한다. GitHub 공개(Chainfire/claude-long-task-agent)로 재현 가능. 기존 [[reddit-claude-code-subagent-prompt-cache-ttl-fix]]에 후속 절로 반영. → [[reddit-claude-code-subagent-prompt-cache-ttl-fix]]

## AX 시사점
오늘 묶음은 "같은 에이전트 기술이 생산성과 공격 양쪽에 동시에 쓰인다"는 하나의 그림으로 모인다. Barclays(전사 확장, 직원 1.6만 명)·Reddit 캐시 최적화(한도 소진 60%↓)는 에이전트를 깊이 들여다볼수록 더 싸고 크게 쓸 수 있다는 쪽이고, CrowdStrike의 한국 은행 해킹 분석은 바로 그 범용성이 공격자에게도 똑같이 열려 있다는 쪽이다. Anthropic이 같은 주에 Cyber Mission(핵심시설 방어+오픈소스 스캐너)과 사용정책 개정을 동시에 내놓은 것은 이 양면성에 대한 공식 대응으로 읽을 수 있다. HN의 "제안 메시지 기능, 진짜 고객은 모델"이라는 비판과 Latent Space의 "클라우드 네이티브 하네스" 제안도 결국 같은 질문으로 수렴한다 — 에이전트 루프·상태·권한을 누가, 어디서, 어떻게 통제하느냐다. Josh Bersin의 HR 멀티에이전트 가이드가 "모델이 아니라 아키텍처가 성패를 가른다"고 못 박은 것도 정확히 이 지점이다. 기업 AX·역량육성 모두에서 "에이전트를 쓰는 법"을 넘어 "에이전트 여러 개를 통제하는 법"으로 교육 비중을 옮겨야 한다는 근거가 오늘 하루에 네 갈래로 쌓였다.
