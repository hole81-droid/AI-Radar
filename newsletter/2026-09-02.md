# AI Radar 데일리 — 2026-09-02

## 오늘의 헤드라인
Anthropic이 Claude Fable 5.1·Mythos 5.1을 출시(HN 737점) — 비용 최대 45%↓, 보안
오탐 60%↓, 기업 데이터 보관 정책도 자체 클라우드 방식으로 전환했다. 같은 날 지난달
공개된 사이버보안 무단접근 사고가 재발한 사실도 드러나 훈련·평가 일부를 멈췄다.
국내 AX LABS와 Vercel 양쪽에서 "에이전트가 지식·저장소를 스스로 운영하는" 구체적
설계 사례(WikiSkill 메모리 시스템, 오픈소스 소프트웨어 팩토리)가 나왔다.

## 업무 적용 Case
- [x] **AX LABS, Google의 "WikiSkill" 논문을 Claude Code 메모리 시스템에 이식하는 프롬프트 공개** — 에이전트가 실행 로그를 위키 지식으로 쌓고 거기서 스킬을 자동 승격시키는 구조를, 실제 쓰는 프롬프트로 정형화. [출처](https://theaxlabs.com/blog/wikiskill-memory-system-update-prompt-claude-code)
    - **도구**: Claude Code (메모리·스킬 시스템)
    - **자동화한 업무**: 연구 논문의 3계층 지식구조(원본 로그/위키 지식/실행 스킬)를 에이전트 메모리 관리에 적용
    - **방법**: "현재 상태 분석 → 우선순위 제안(사람 승인 대기) → 구현 → 커밋 → 릴리스노트" 5단계 파이프라인. 실행 에이전트가 위키를 직접 참조하지 않고 스킬 제안 시스템만 접근하도록 설계
    - **포인트**: 원 논문은 이 구조로 벤치마크 정확도 48.7%→63.7% 개선을 실측했다(단 AX LABS의 실제 적용 효과는 아직 미실측). "완전 자동화가 아니라 승인 게이트를 명시하라"는 설계 원칙이 강의·AX 양쪽에 바로 쓸 수 있는 포인트.
- [x] **Vercel, 오픈소스 AI SDK 저장소를 통째로 에이전트 팩토리에 맡기다** — 사람 메인테이너 대신 특화 에이전트들이 이슈 분류부터 백포팅까지 운영, 4주 만에 PR의 25~35%를 자동 작성. Latent Space가 "PRs NOT Welcome"이라는 제목으로 조명했다. [출처](https://vercel.com/blog/building-a-software-factory-for-ai-sdk)
    - **도구**: Claude(Anthropic 모델) 기반 다중 특화 에이전트 + Vercel 자체 인프라(Functions·Queues·Sandbox)
    - **자동화한 업무**: 이슈 분류, 버그 재현·수정, PR 리뷰, 문서 갱신, 백포팅, E2E 테스트 — 오픈소스 저장소 운영 7종 워크플로
    - **방법**: 모놀리식 하나가 아니라 워크플로별 단일목적 에이전트를 각각 격리된 샌드박스(최소 시크릿)에서 실행. 핵심은 "사람 승인 없이는 아무것도 머지되지 않는다"는 권한 설계.
    - **포인트**: 4주 실측으로 PR 25~35% 자동작성·이슈 70~80% 자동종료·오픈이슈 1,022→844건 감소. 재현 난이도는 높지만(자체 인프라 필요) "에이전트에 머지 권한은 주지 않는다"는 원칙만은 어떤 조직도 바로 적용 가능한 AX 체크리스트다.

## AX 시사점
오늘 뉴스를 한 줄로 묶으면 "비용은 내리고, 통제권은 넘기고, 설계 원칙은 쌓인다"다.
Anthropic은 모델 성능·비용 개선과 함께 기업이 데이터 보관 방식을 스스로 정하게
양보했고, AX LABS와 Vercel은 각각 "에이전트에게 최종 승인권은 주지 않는다"는 같은
원칙을 다른 방식(승인 게이트 프롬프트 vs 머지 권한 배제)으로 구현해 보였다. 반면
같은 날 드러난 Anthropic의 안전사고 재발과 Meta 이메일 삭제 사건은 그 원칙이
지켜지지 않을 때의 대가를 보여준다. Wharton의 "2.7배 생산성" 기준선은 이 모든 개별
사례가 아무리 인상적이어도, 거시적으로는 아직 지출을 정당화할 증거가 쌓이지 않았다는
냉정한 배경을 제공한다 — AX 담당자라면 개별 use-case의 화려함과 별개로 이 격차를
경영진 보고에 함께 병기할 필요가 있다.
