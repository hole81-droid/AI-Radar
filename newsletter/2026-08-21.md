# AI Radar 데일리 — 2026-08-21

## 오늘의 헤드라인
Salesforce가 팀 전체가 함께 코드를 짜는 협업 공간 "Slack Code"를 출시했다 — Claude
Code·Devin·v0·ChatGPT 등 여러 AI 에이전트를 한 채널에서 같이 쓰고, 프로덕션 배포는
사람이 승인해야 한다. 같은 주 Asana는 Codex 에이전트 4개를 병렬로 돌려 "5년짜리"로
추정됐던 테스트 프레임워크 마이그레이션을 2주 만에 끝냈다고 밝혔다(비용 $6M 추정→
$12,000). 그런데 정작 여론조사에서는 미국인의 AI 우려가 5년 새 37%→52%로 늘었고,
Anthropic CEO Dario Amodei는 이를 "신뢰의 위기"라고 인정했다.

## 업무 적용 Case
- [x] **Asana, Codex 병렬 에이전트로 "5년짜리" 테스트 마이그레이션을 2주 만에 끝내다** — 낡은 테스트 프레임워크 Enzyme을 React Testing Library로 전면 교체, 사내 원래 추정은 5년·$600만이었다. [출처](https://openai.com/index/asana/) → [[asana-openai-codex-enzyme-migration]]
    - **도구**: OpenAI Codex(구체 모델 버전은 비공개)
    - **자동화한 업무**: 레거시 테스트 프레임워크(Enzyme) → React Testing Library 전면 마이그레이션
    - **방법**: 다섯 문장짜리 프롬프트로 시작해 최대 4개 Codex 에이전트가 코드베이스 사본에서 병렬 작업. 엔지니어 1명이 매일 2회 진행상황을 검토하고 모든 변경을 승인.
    - **포인트**: 비용은 $6M 추정→$12,000(약 500배)로 줄었다는 벤더(OpenAI) 발표지만, HN에서는 "원래 5년 추정치 자체가 파트타임 기준 아니냐", "코드 품질 동등성을 제3자가 검증할 방법이 없다"는 회의론이 강하다. 요구사항이 명확한 레거시 제거 작업이 병렬 에이전트의 첫 적용 대상으로 적합하다는 근거로 쓰되, 수치는 "주장"으로 다룰 것.

- [x] **"/wayfinder" — 목표가 불분명한 프로젝트를 위한 Claude Code 기획 스킬** — 구루 채널 Latent Space가 소개한, 맵·티켓·세션 3단 구조로 기획 단계 자체를 관리하는 스킬. [출처](https://www.latent.space/p/wayfinder-skill) → [[latent-space-wayfinder-claude-code-skill]]
    - **도구**: Claude Code Skill(제작자 Matt Pocock)
    - **자동화한 업무**: "무엇을 해야 할지조차 불분명한" 그린필드 프로젝트의 기획 단계 관리
    - **방법**: 전체 컨텍스트를 담는 맵 문서, 개별 과제인 티켓(grilling·prototype·research·task 4종), 실행 단위인 세션의 3계층 구조. 부모 세션이 자식 세션에 좁은 과제+전체 개요만 위임해 토큰 제약을 우회.
    - **포인트**: 제작자 본인이 20년 치 콘텐츠가 쌓인 개인 웹사이트 재설계에 적용해 검증한 수준(벤치마크 수치 없음). "루프 엔지니어링"의 연장선으로, 기획 단계 자체를 계층 시스템으로 다루는 최신 방법론 사례로 강의에 적합.

- [x] **"AI 에이전트를 팀원으로 쓰는 법" — Slack CPO가 공개한 5원칙** — Slack CPO Jaime DeLanghe의 Anthropic 인터뷰를 AX LABS가 정리. [출처](https://theaxlabs.com/blog/slack-human-agent-team-principles) → [[theaxlabs-slack-cpo-ai-teammate-principles]]
    - **도구**: Claude(Slack 연동)
    - **자동화한 업무**: Slack 대화·회의·문서 로그의 지식베이스화, 일일 브리핑·후속 작업 실행
    - **방법**: 대화 로그를 지식소스로 취급 → 에이전트는 준비·실행만, 사람은 이모지 반응으로 승인·우선순위 지정 → 에이전트마다 존재 이유 한 줄 명시 → 공개 채널 기본값 → 시연(show-and-tell)으로 확산.
    - **포인트**: 정량 수치는 없는 원칙 중심 콘텐츠라 도입 근거보다 "운영 체크리스트"로 쓰기 좋다. "토큰량·메시지량은 가치의 증거가 아니다"라는 경고가 AX 도입 초기 흔한 착각을 짚는 반례로 유용. 같은 날 발표된 Slack Code 출시와 메시지가 직접 연결된다.

## AX 시사점
오늘은 "에이전트가 팀 워크플로 안으로 들어오는 속도"와 "일반 대중의 신뢰"가 반대 방향을
가리킨 하루다. Slack Code(팀 채널 상주)와 Google Chat(전사 AI 허브화)은 에이전트를 사내
커뮤니케이션 도구 안으로 통합하는 경쟁이 본격화됐음을 보여주고, Asana의 "500배 절감"
주장은 구체적 ROI 스토리가 계속 쌓이고 있음을 보여준다. 하지만 같은 시점에 Pew 조사는
일반 대중의 AI 불안이 커지고 있다는 걸 보여주며, Anthropic CEO조차 이를 인정했다. AX
전략에서는 "내부 도입 속도"와 "외부 커뮤니케이션·신뢰 구축"을 별개 트랙으로 관리해야
한다는 시사점이다 — 특히 벤더가 제시하는 ROI 수치(오늘의 Asana 500배, 어제의 AX LABS
80% 절감)는 전부 벤더·고객사 자체 주장(claimed)이라는 점을 명시하지 않으면 오히려
신뢰 위기를 키우는 역효과가 날 수 있다.
