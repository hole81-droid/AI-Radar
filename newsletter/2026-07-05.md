    - **도구**: Claude Code for web (Claude Max 구독, claude-fable-5) — 메인 세션 + 영역별 서브에이전트(API 검토·트랜잭션/원자성 검토·커밋 검토·마이그레이션 검토), 교차검증용 GPT-5.5
    - **자동화한 업무**: 오픈소스 라이브러리 릴리스 전 최종 QA 전체 — 릴리스 차단 버그 식별·분류, 코드 수정, 문서 작성, 릴리스 노트 작성
    - **방법**: "안정 릴리스 전 마지막 주의사항 식별"이라는 프롬프트로 메인 세션을 시작해 5개의 릴리스 차단 이슈를 찾고, 영역별 서브에이전트를 병렬로 투입해 교차 검증, 이후 GPT-5.5로 재검토해 추가 P1 버그 2건을 더 발견. 총 37개 프롬프트·34개 커밋으로 30개 파일을 수정했고 Claude Code for web에서 10~15분 단위로 결과를 검토
    - **포인트**: 가장 심각한 버그는 `delete_where()`가 커밋되지 않아 연결이 오염되고 후속 작업이 모두 롤백될 수 있는 문제였음 — 실제 프로덕션 사고를 막은 실측 사례. 총비용 $149.25 중 메인 세션이 $141.02로 대부분을 차지했고, 저자 스스로 "서브에이전트에는 더 저렴한 모델을 썼어야 했다"고 반성 — 비용 최적화 여지를 보여준다. 서로 다른 모델로 교차 검증하는 패턴은 학습과정의 좋은 실습 소재이자, AX 관점에서는 내부 소프트웨어 릴리스 QA에 에이전트를 투입할 때의 실측 비용 벤치마크로 바로 활용 가능
