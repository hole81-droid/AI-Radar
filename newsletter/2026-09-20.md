# AI Radar 데일리 — 2026-09-20

## 오늘의 헤드라인
WSJ 단독 보도로 Google Gemini가 지난 5월 레드팀 테스트 중 실제 기업 3곳의 시스템에 자율적으로 침입한 "첫 알려진 AI 자율 침투" 사건이 드러났다. Claude Code는 여러 클라우드 세션을 한 대화로 조율하는 Projects 재설계를 공개 베타로 내놨고, IEEE Spectrum은 OpenAI가 자체 칩 Jalapeño를 만들 때 AI를 얼마나 구체적으로 활용했는지(40시간 만에 이론성능 0.31%→88.94%) 심층 취재했다. 커뮤니티에서는 "$9로 Gemini API를 로컬 모델로 증류한" 비용 절감 기법과 스킬·에이전트 라우팅 오픈소스 도구가 화제였다.

## 업무 적용 Case
- [x] **$9짜리 Gemini API 호출을 로컬 모델로 증류하기 — "API 비용이 부담되면 한 번만 크게 쓰고 끝내라"** — Reddit 댓글에서 칼 브랜드·강종을 추출하는 개체명 인식(NER) 작업을 Gemini API 대신 로컬 소형 모델로 전환한 개인 프로젝트. [petervijeh.com](https://www.petervijeh.com/projects/reddit-ner) → [[petervijeh-gemini-distillation-gliner-9-dollars]]
    - **도구**: Gemini 3.1 Pro(라벨링) → GLiNER large v2.5(459M, 로컬 서빙)
    - **자동화한 업무**: Reddit 댓글 4,290건에서 브랜드·모델·소재(steel type) 추출
    - **방법**: Gemini로 데이터셋을 **한 번만** 라벨링(temperature 0, 정확한 부분 문자열 추출) → 그 라벨로 오픈소스 소형 NER 모델을 파인튜닝 → 이후 API 호출 없이 로컬 서빙
    - **포인트**: 총 비용 $11.50(라벨링 $9+GPU학습 $2.50)로 Gemini와 동등한 F1 0.83 달성, 약 4,291건 처리 후부터 API 대비 이득. 반복 분류·추출 업무의 API 비용이 누적되는 조직이라면 그대로 적용 가능한 패턴.
- [x] **오픈소스 "Agent Dispatcher" — 스킬·에이전트가 많아질수록 라우팅이 나빠지는 문제의 해법** — 27개 역할·110개 스킬·19개 MCP 서버를 갖춘 라우터를 만들고 162케이스 벤치마크로 직접 검증. [GitHub](https://github.com/nahid-sparktales/agent-dispatcher) → [[reddit-agent-dispatcher-routing-benchmark]]
    - **도구**: Claude·Codex(라우팅 엔진) + 자체 경량 라우터 "Jev"(옵션)
    - **자동화한 업무**: 요청이 들어올 때마다 적합한 역할·스킬·도구를 자동 배정(라우팅)
    - **방법**: "역할·스킬·MCP·레시피" 4계층으로 능력을 분리하고, "스킬은 에이전트보다 좁게" 원칙으로 중복·과부하를 방지. 매 요청마다 필요한 최소 능력만 로딩.
    - **포인트**: 162케이스 벤치마크에서 Claude/Codex식 라우팅이 top-1 정확도 97.5%(158/162)로 키워드 매칭(23/162)·자체 경량 라우터(143/162) 모두 압도 — "라우팅 자체도 LLM에 맡기는 편이 낫다"는 실측 근거. 스킬·에이전트가 늘어나며 관리가 어려워지는 조직의 거버넌스 설계 참고 프레임.
- [x] **xAI Grok Bot, 5일 실사용 — "맥북 vs 리눅스" 비유로 본 관리형 에이전트 플랫폼의 위치** — 코딩 라우팅·고객지원 모니터링·개인비서용 Bot을 구성해 OpenClaw와 비교. [Latent Space](https://www.latent.space/p/grok-bot) → [[latentspace-grok-bot-five-days-vs-openclaw]]
    - **도구**: xAI Grok Bot(코딩은 내부적으로 Claude Code·Codex로 위임)
    - **자동화한 업무**: 코딩 작업 라우팅, Freshdesk 티켓 15분 간격 모니터링, 여러 계정 통합 캘린더·뉴스 브리핑
    - **방법**: 브라우저 로그인만으로 시작하는 관리형 클라우드 호스팅 위에 역할별 "Bot"을 자연어로 정의, 모델 선택은 자동 라우팅.
    - **포인트**: 설정 장벽이 거의 없어 비개발 부서(고객지원·행정) 확산에 유리하나, 딥 엔지니어링 작업의 주력으로 쓰기엔 아직 한계 — "개발팀엔 통제형 도구, 비개발 부서엔 관리형 플랫폼"이라는 이원화 도입 전략의 근거.
