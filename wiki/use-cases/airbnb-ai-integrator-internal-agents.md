> **공식**: Airbnb가 사내 에이전트(AirChat)와 조직 컨텍스트 그래프(Everest, mcp+subagents)를 활용해 신규 서비스 개발·온콜 대응·고객 지원을 수행 → 코드 60% AI 저작, 기능 출시량 약 80%↑, PR 처리량 1.6배, 지원 티켓 약 45~50% AI 단독 해결

## 무엇을 자동화했나

전 Meta Llama 모델 총괄 Ahmad Al-Dahle가 이끄는 Airbnb AI 조직이 "Inside-Out AI" —
사내 개발 방식부터 게스트용 제품까지 — 전반에 에이전트를 투입한 사례. 핵심은 둘이다.

1. **제너럴리스트가 전문 영역 코드를 건드릴 수 있게 하는 컨텍스트 공유**: 식료품
   배달(8~9개월), 공항 픽업(6주) 같은 신규 서비스를 소수 인원이 빠르게 론칭.
2. **이벤트 기반 비동기 에이전트의 운영 업무 흡수**: 모니터링 알림 발생 시 컨테이너에서
   자동으로 온콜 사고를 트리아지하고, 고객 지원 티켓의 절반 가까이를 AI가 단독 종결.

## 어떻게 구성했나 (아키텍처)

- **AirChat**: 제품팀이 쓰는 사내 에이전트. 필요한 MCP 조직 컨텍스트를 자동으로 포함해
  팀 간 지식 격차를 메운다.
- **Everest**: LLM+임베딩+AI 기반 검색으로 만든 "조직 컨텍스트 그래프". 코드베이스·
  문서·조직 지식을 그래프화해 비전문가도 전문 영역 코드에 안전하게 접근·수정 가능.
- **비동기 온콜 에이전트**: 모니터링 알림이 트리거가 되면 컨테이너에서 자동 기동해
  사고를 트리아지 — 사람 개입 전 1차 분류·대응까지 수행.
- **코드 우선(code-first) 개발 문화**: 요구사항 문서 대신 프로토타입·동작하는 코드를
  1차 산출물로 삼는 방향으로 팀 운영 방식 자체를 전환.
- **AI 보조 PR**: 에이전트가 수정안을 생성하면 사람 엔지니어가 검토·병합하는 휴먼인더루프
  구조 유지.
- **멀티모델 전략**: 프로덕션에 최소 10개의 커스텀 모델을 운영하며 유스케이스별 비용·
  성능·지연시간 파레토 프론티어로 모델을 선택(특정 벤더 종속이 아님).

## 성과와 수치

- 코드의 **60%**가 AI 저작 (claimed)
- 전년 대비 기능 출시량 약 **80% 증가** (claimed)
- 평균 엔지니어 **PR 처리량 1.6배** (claimed)
- 고객 지원 티켓의 **약 45~50%**를 AI가 단독 해결, 안전 이슈는 사람이 유지 (claimed)
- 신규 서비스 론칭 기간: 식료품 배달 8~9개월, 공항 픽업 6주 (claimed, 비교 기준선 비공개)

> 전부 Airbnb AI 책임자 본인이 밝힌 수치이며, 측정 기간·비교 기준선·제3자 검증 여부가
> 공개된 인터뷰 구간에는 나오지 않는다. 자사 긍정 사례 위주로 구성됐을 가능성을 감안해
> 읽을 것.

## 재현 가이드

**난이도: 상** (조직 전체 컨텍스트 그래프 구축이 전제조건)

- **준비물**: 코드베이스·문서·조직 지식을 연결할 임베딩·검색 인프라, MCP 등으로 사내
  도구에 에이전트가 접근할 수 있는 통합 계층, 온콜 알림 시스템과 연동 가능한 컨테이너
  기반 에이전트 실행 환경.
- **핵심 단계**:
  1. 조직 지식(코드·문서·과거 의사결정)을 하나의 검색 가능한 컨텍스트 그래프로 통합
     (Everest에 해당하는 자체 구축 필요 — 상용 솔루션 특정 안 됨).
  2. 제품팀 전용 에이전트에 이 컨텍스트를 기본 탑재해 제너럴리스트도 전문 영역 작업이
     가능하게 설계.
  3. 모니터링 알림 → 컨테이너 자동 기동 → 1차 트리아지의 비동기 파이프라인 구축.
  4. AI가 생성한 PR·지원 응답은 사람이 검토·승인하는 게이트를 유지(완전 자율화 아님).
  5. 단일 모델이 아니라 유스케이스별 비용·성능·지연시간을 따져 모델을 라우팅하는
     멀티모델 운영 체계로 설계.

## 강의·AX 활용 포인트

- **AX**: "에이전트를 개별 작업에 붙이기"가 아니라 "조직 컨텍스트 자체를 그래프화해
  제너럴리스트의 전문영역 접근을 넓힌다"는 접근은 대규모 조직의 AI 전환 설계에 참고할
  만한 프레임이다. 코드 작성뿐 아니라 온콜·고객지원까지 같은 컨텍스트 인프라로 묶은
  점이 특징.
- **강의**: "AI 책임자 본인 인터뷰" 성격의 claimed 수치를 어떻게 비판적으로 읽을지
  설명하는 사례로도 쓸 수 있다 — 측정 방법론 비공개, 비교 기준선 불명확이라는 한계를
  짚어가며 다루면 좋다.
