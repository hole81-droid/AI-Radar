# Mollick, Claude 5 Fable 조기 체험기 — "나는 더 이상 마법사가 아니라 의뢰인이다"

> **채택 근거(화제성)**: One Useful Thing(Ethan Mollick), 2026-06-09 발행. 좋아요
> 2,190건 — 이 뉴스레터 자기 평균(1,136.9건)의 약 1.9배로, 이번 백필 대상 기간
> 중 One Useful Thing에서 가장 높은 참여도를 기록한 글(과제 지정 후보 C13).
> Mythos급 모델의 **일반 공개 전 조기 접근(early access)** 리뷰다 — 이 위키의
> 기존 [[2026-07-01-claude-fable-5-global-return]] 페이지 등이 다룬 **모델
> 출시·규제·요금 이벤트**와는 다른 각도로, **실제 사용 경험**을 구조화해 기록한다.

## 공식

> **공식**: Claude Code로 vibe-coding·서브에이전트 위임을 활용해 연구 집약적
> 소프트웨어(교통시간지도, 통계 보정 도구)를 제작 → 전문가 한 명이 수년째
> 필요하다고 느꼈던 도구를 수 시간 자율 실행만으로 완성, 단 사용자 체감상
> 결과에 대한 통제권은 "조종(steer)"에서 "위탁(commission)"으로 이동.

## 무엇을 자동화했나

Mollick(Wharton 교수)이 Mythos급 모델 **Claude 5 Fable**(보안 관련 용도는
가드레일로 차단된 조기 접근판)로 소프트웨어 리서치 프로젝트 2건을 실험했다.

1. **등시선 지도(isochrone map)** — 특정 도시에서 주어진 시간 안에 갈 수
   있는 범위를 보여주는 지도(원본은 1881년 런던 기준으로 제작된 것이 최초).
   이전의 어떤 모델도 절반만큼도 쓸만하게 만들지 못했던 과제.
2. **Concord** — 사람과 AI의 판단(예: "이 아이디어가 얼마나 혁신적인가")을
   통계적으로 보정·비교하는 연구용 분석 소프트웨어. "연구자들이 수년간
   필요로 했지만 수익성이 없어서 아무도 안 만든" 도구.

## 어떻게 구성했나 (아키텍처)

- **단일 자연어 프롬프트**로 시작 — 예: "공항·기차·도보·자동차 이동시간을
  반영한, 실제 데이터 기반의 등시선 지도를 만들어줘. 몇 개 도시로 시작해도
  되지만 일반화될수록 좋다."
- Fable이 스스로 **다른 AI(주로 더 저렴한 Claude Sonnet)를 서브에이전트로
  여러 개 기동**해 항공편 2,200편 이상, TGV~신칸센 등 철도 시간표, 국가별
  도로 속도 데이터를 리서치. 동시에 코딩을 진행하고, 검증용 에이전트·테스트를
  추가로 기동.
- 피드백 루프: "그린란드 등 오지의 이동시간이 추정치뿐이다 → 실제 데이터를
  가져와라"라고 지시하자, **적대적으로 서로의 결과를 검증하는 에이전트 그룹
  워크플로**를 새로 구성해 대응(피트케언 섬 선박 운항 빈도, 오타와→그리즈
  피오르 이동경로까지 조사).
- Concord 프로젝트는 **19페이지 설계 문서**를 먼저 생성한 뒤 **9.5시간
  연속 자율 실행**으로 구현까지 완료.

## 벤치마크 데이터

| 항목 | 값 |
|---|---|
| 모델 | Claude 5 Fable(Mythos급, 조기 접근판). 코드 자체에 "Claudisms"(특유의 문체) 흔적이 남는다고 저자가 언급 |
| 비용 | 미확인 — 원문은 "Fable은 Opus 대비 토큰 단가 2배이며 매우 빠르게 토큰을 소모한다. 다만 저렴한 모델로의 위임이 실비용을 상당히 낮출 수 있다"고만 서술 |
| 권한 | 미확인 — 가드레일이 보안 관련 프롬프트에 극도로 민감하게 반응해 자주 하위 모델(Claude 4.8 Opus)로 자동 다운그레이드된다는 언급만 있음 |
| 성숙도 | demo(저자 개인 실험, 프로덕션 배포 아님) |

## 성과와 수치

- 등시선 지도: 완성도 높은 결과물이었으나 **완벽하지는 않음** — 오지 지역
  추정치 오류를 저자가 직접 발견해 재작업 지시. (evidence: anecdotal, 저자
  1인의 정성 평가)
- Concord: 저자가 전문가로서 일부 오류·누락을 발견해 AI에게 수정 지시.
  "완벽하지 않지만, 지금까지 본 어떤 산출물보다 범위가 컸다"고 평가.
- 정량적 성과 지표(정확도·오류율·시간 절감 배수)는 **원문에 없음 —
  미확인**으로 남긴다.

## 재현 가이드

- **난이도**: 상 (모델 접근권 자체가 조기 접근 제한, Mythos급 모델 필요)
- **준비물**: Mythos급 에이전틱 코딩 모델 접근권(Claude Code 등), 명확하지만
  개방적인 리서치형 프롬프트, 검증할 전문성을 가진 사용자(산출물 오류를
  스스로 잡아낼 수 있어야 함)
- **핵심 단계**:
  1. 결과물의 형태만 지정하고 방법은 위임하는 **개방형 프롬프트** 작성
  2. 진행 중 결과를 보고 **"이 부분은 부정확하다"는 식의 구체적 피드백**만
     추가로 제공 — 세부 실행 방식은 계속 AI에 맡김
  3. 완성 후 **전문가로서 직접 결과를 검증**(저자 본인이 오류를 발견한
     방식) — 이 단계를 생략하면 오류가 그대로 남는다

## 강의·AX 활용 포인트

- **강의**: "조종(steer)에서 위탁(commission)으로"라는 저자의 자기 진단은
  에이전틱 AI 리터러시 교육에서 **"내가 이 결과의 어디까지 이해하고
  책임질 수 있는가"**를 스스로 점검하게 하는 토론 소재로 강력하다. 저자
  본인의 표현: *"나는 더 이상 마법사가 아니라 후원자(patron)에 가깝다.
  나는 원하는 것을 설명하고, 값을 지불하고, 결과를 판단한다. 주문(conjuring)은
  내가 볼 수 없는 곳에서, 내가 한 번도 투표하지 않은 수백 개의 작은
  선택으로 일어난다."*
- **AX**: 에이전트에게 장시간 자율 실행을 맡길 때 "결과를 검증할 전문성이
  조직 내부에 있는가"가 도입 전제조건이 된다는 시사점 — 이 사례의 성공은
  Mollick 본인이 전문가로서 오류를 잡아낼 수 있었기에 가능했다.
- **한계**: 단일 사용자(저자 본인)의 조기 접근 체험이며, 통제된 실험이
  아니다. 비용·권한·정량 성과 지표는 대부분 미확인이다.
