# Claude Design, "DESIGN.md → 디자인 시스템 → 재사용 템플릿" 3단계로 일반화하기

> **공식**: Claude(Claude Design 기능, prd-driven)로 DESIGN.md+디자인 시스템+재사용 템플릿
> 3종 입력 파일을 준비해 슬라이드·소셜 카드·뉴스레터 등 시각 자료 제작을 수행
> → 매 생성물이 "일반적인" 결과 대신 브랜드에 맞는 결과로 나오도록 구조화

## 무엇을 자동화했나

생산성 유튜버 Jeff Su는 "대부분의 Claude Design 튜토리얼이 템플릿 하나 고르고 바로 프롬프트치라고
하는데, 그래서 결과물이 뻔하게 나온다"고 지적하며, 프롬프트 전에 준비해야 할 3개의 입력 파일 —
DESIGN.md 파일, Claude Design 안의 디자인 시스템, 재사용 가능한 프레젠테이션 템플릿 — 을 만드는
과정을 시연했다. 이 영상은 슬라이드를 예로 들지만 동일한 워크플로가 소셜 카드·뉴스레터 등
다른 시각 자료 제작에도 그대로 적용된다고 소개한다.

## 어떻게 구성했나 (아키텍처)

- **입력 #1 — DESIGN.md**: 공개 GitHub 저장소에서 기본 DESIGN.md 템플릿을 가져와 ChatGPT로
  다듬어 프로젝트 성격에 맞게 정리.
- **입력 #2 — 디자인 시스템**: 정리된 DESIGN.md를 Claude Design 안에서 색상·타이포그래피·레이아웃
  규칙을 담은 재사용 가능한 디자인 시스템으로 변환.
- **입력 #3 — 재사용 템플릿**: 디자인 시스템을 기반으로 한 프레젠테이션 템플릿을 제작, 이후
  피드백을 줄 때마다 템플릿 자체가 개선되도록 반복.
- **핵심 주장**: "템플릿 고르고 프롬프트 → 뻔한 결과"가 아니라 "브랜드 컨텍스트 파일을 먼저
  갖추고 → 템플릿화 → 반복 개선"하는 순서가 일관되고 온브랜드한 결과를 만든다는 것.

## 성과와 수치

- 정량적 개선 수치(제작 시간 단축 등)는 원문에 없음 — **일화(anecdotal)** 수준의 워크플로 소개.
- "Real Proof"라는 챕터로 결과물 스크린샷을 제시하지만 별도 측정치는 없음.

## 재현 가이드

- **난이도**: 하
- **준비물**: Claude(Design 기능 접근), 공개 DESIGN.md 템플릿(GitHub), ChatGPT(선택, 정리용)
- **핵심 단계**:
  1. GitHub에서 공개된 DESIGN.md 템플릿을 가져와 자신의 브랜드에 맞게 다듬는다
  2. Claude Design 안에서 이 DESIGN.md를 디자인 시스템으로 변환한다
  3. 디자인 시스템 기반 재사용 템플릿을 하나 제작한다
  4. 이후 결과물에 피드백을 줄 때마다 템플릿 자체를 개선해 다음 생성물의 품질을 끌어올린다
  5. 같은 3단계 구조를 슬라이드 외에 소셜 카드·뉴스레터 등에도 그대로 적용한다

## 강의·AX 활용 포인트

- **강의**: "좋은 프롬프트"보다 "좋은 컨텍스트 파일(DESIGN.md)"이 반복 가능한 품질을 만든다는
  점에서, 이 위키 자체의 `web/DESIGN.md` 운영 방식과 같은 원리 — 비개발자 대상 실습(슬라이드
  제작)으로 "스펙 먼저, 생성은 나중" 개념을 가르치기 좋은 소재.
- **AX**: 마케팅·기획 부서가 매번 디자이너 없이 온브랜드 산출물을 뽑아내려 할 때, "회사 디자인
  가이드를 DESIGN.md 하나로 코드화 → 템플릿화"하는 초기 세팅 비용만 들이면 이후 반복 생성 비용이
  낮아진다는 시사점.
