> **공식**: Claude(Anthropic 모델 기반 다중 전문 에이전트)로 subagents·cli-pipeline을
> 활용해 오픈소스 저장소의 이슈 트리아지·버그 수정·PR 리뷰·문서·백포팅·E2E 테스트
> 7종 워크플로를 자동화 → 4주 만에 PR의 25~35%·이슈의 70~80%를 자동 처리

## 무엇을 자동화했나

Vercel이 자사 오픈소스 프로젝트 **AI SDK** 저장소 운영을 위해 만든 "소프트웨어
팩토리"— 사람 메인테이너 대신 특화된 단일목적 에이전트 여러 개가 상시 돌아가며
저장소를 운영하는 시스템이다. Latent Space가 "PRs NOT Welcome"이라는 제목으로
이 사례를 조명하며(Astro·Flue·tldraw 등 다른 오픈소스 프로젝트들도 유사하게 "드라이바이
커뮤니티 PR"을 소프트웨어 팩토리로 대체하는 흐름을 함께 다룸), Vercel 공식 블로그가
운영 원리와 4주 실측 수치를 공개했다.

자동화 대상 7개 워크플로:
- 이슈 분류(버그/기능/문서)
- 버그 재현 및 수정
- PR 리뷰·승인
- 기능 분석 및 구현
- 문서 갱신
- 구버전 백포팅
- 실제 증거를 남기는 E2E 테스트

## 어떻게 구성했나 (아키텍처)

**단일목적 특화 에이전트**(모놀리식이 아닌) 다수를 운영하는 구조. 각 에이전트는
자기 코드·런타임·해당 작업에 필요한 최소한의 시크릿만 담긴 **격리된 Vercel Sandbox**
안에서 실행된다. 인프라는 Vercel 자체 스택으로 구성:

- **Vercel Functions** — API·워커·웹훅 수신
- **Vercel Queues** — 작업 큐잉·실행
- **Vercel Blob** — 로그 저장
- **Vercel Sandbox** — 에이전트별 격리 작업공간
- **Neon Postgres** — 팩토리 운영 데이터

가장 중요한 설계 원칙: **"사람 승인 없이는 아무것도 머지되지 않는다"** — 완전
자동화가 아니라 사람이 최종 배포 권한을 쥔 반자동 구조다.

## 벤치마크 데이터

| 항목 | 내용 |
|---|---|
| 모델 | 미확인 (Anthropic Opus 4.6을 "PR 급증 변곡점" 계기로 언급하나 팩토리 주력 모델 명시 없음) |
| 비용 | 미확인 |
| 권한 설계 | 에이전트별 격리 Sandbox(최소 시크릿) + 사람 최종 승인 필수(머지 권한 없음) |
| 성숙도 | production (Vercel 자사 핵심 오픈소스 저장소에 실제 운영 중) |
| evidence | measured (4주 운영 실측 수치 공개) |

## 성과와 수치 (4주 실측, measured)

- 주간 PR의 **25~35%**를 팩토리가 작성
- 이슈의 **70~80%**를 자동으로 종료 (7월 한 달 종료 건의 75%가 팩토리 생성)
- 오픈 이슈 **1,022건 → 844건**으로 감소
- v6 백포팅의 **50% 이상**이 자동화됨

## 재현 가이드

- **난이도**: 상 (자체 인프라 구축 필요 — 서버리스 함수·큐·샌드박스·DB를 조합한
  플랫폼 엔지니어링 작업이라 소규모 팀이 그대로 복제하기는 어렵다)
  - 준비물: 서버리스 함수/큐 인프라(또는 동등한 자체 오케스트레이션), 격리 실행
    환경(샌드박스/컨테이너), 이슈·PR 이벤트를 받는 웹훅 연동, 사람 승인 단계를
    강제하는 머지 정책
  - 핵심 단계:
    1. 모놀리식 하나가 아니라 워크플로별(트리아지/버그수정/리뷰/문서/백포팅/테스트)
       **단일목적 에이전트**로 분리 설계
    2. 각 에이전트를 해당 작업에 필요한 최소 권한·시크릿만 가진 격리 환경에서 실행
    3. 이슈·PR 웹훅을 큐에 적재해 비동기로 처리
    4. **사람 승인 게이트를 머지 권한 자체에 하드코딩** — 에이전트에 머지 권한을
       주지 않는 것이 핵심 안전장치
    5. 처리 결과(재현 스크린샷·테스트 로그 등)를 사람이 검토 가능한 형태로 남기기

## 강의·AX 활용 포인트

- **강의**: "AI가 코드를 짠다"를 넘어 "AI가 오픈소스 저장소 운영 자체를 대체한다"는
  사례로, 에이전트 오케스트레이션을 인프라 수준(서버리스+큐+샌드박스)에서 가르칠
  때 좋은 실전 레퍼런스. 같은 흐름(Astro·Flue·tldraw)과 묶어 "소프트웨어 팩토리"
  트렌드로 소개할 수 있다.
- **AX**: 개발팀 규모 대비 이슈·PR 적체가 심한 조직이라면, 전면 자동화 대신 "머지
  권한은 사람에게 남기고 그 앞단(분류·재현·초안 작성)만 에이전트에 맡기는" 단계적
  도입 모델의 실측 벤치마크로 인용할 수 있다. 오픈 이슈 감소·백포팅 자동화 수치는
  ROI 논의에 바로 쓸 수 있는 정량 근거.
