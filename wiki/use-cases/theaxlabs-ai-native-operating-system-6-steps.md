# AX LABS "AI 네이티브 운영체제" 6단계 가이드 — 툴별 AI 붙이기의 대안

> **공식**: 특정 AI Tool이 아닌 모델 계층화 라우팅(소형/중형/프론티어) 아키텍처를 활용해
> 중소기업의 업무 매핑→데이터 모델→에이전트 배치→백그라운드 자동화 전 과정을 재구축
> → 창고·물류사 사례에서 AI 비용 80%+ 절감·인당 주당 60시간 수작업 제거

## 무엇을 자동화했나

AX LABS 블로그가 정리한 "툴마다 AI를 하나씩 붙이는 방식(point solution)은 왜 실패하는가"에
대한 대안 방법론. 개별 SaaS 툴에 AI 기능을 각각 붙이는 대신, 업무 전체를 관통하는 하나의
"AI 네이티브 운영체제"를 구축하는 6단계 절차를 제시한다. 타겟은 연 매출 30~150억 원,
직원 20명 내외 규모 기업.

## 어떻게 구성했나 (아키텍처)

**모델 계층화(라우팅) 전략**이 핵심 메커니즘이다:
- 소형·저가 모델 — 항목 추출·분류 (전체 호출량의 70%)
- 중형 모델 — 요약·초안 작성 (22%)
- 프론티어 모델 — 판단·설계 (8%)

**6단계 구축 절차**:
1. **업무 매핑** — 현재 워크플로를 지도화
2. **툴 정리** — 기존 툴을 흡수/유지/폐기로 분류
3. **데이터 모델 설계** — 단일 진실 원천(single source of truth) 구축, 이 단계에서 조회
   권한도 사전 정의
4. **코어 구축** — 자동화 없이 시스템 간 연결만 먼저 완성
5. **AI 에이전트 배치** — 문서 인테이크(PDF·이메일 처리), 문서 생성(제안서·보고서),
   운영 질의(DB 조회), 라우팅·분류 4개 영역에 에이전트 투입
6. **백그라운드 자동화** — 상태 변화를 트리거로 하는 자동 실행

**검증 체계**: 스키마 기반 추출 시 JSON에 `confidence`·`needs_review` 필드를 포함시키고,
초기 2~4주는 전건을 사람이 검토하며 정확도를 측정한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | 미확인 — 3단계 모델 계층 전략만 명시, 특정 벤더·모델명 없음 | AX LABS 원문 |
| 비용 | AI 비용 80%+ 절감(모델 라우팅 효과, 원문 주장) | AX LABS 원문 |
| 권한 설계 | 데이터 모델 설계 단계에서 조회 권한 사전 정의 — 구체 ACL 방식은 미확인 | AX LABS 원문 |
| 성숙도 | production — 창고·물류사 사례가 450개 프로젝트를 단일 시스템으로 실제 운영 중 | AX LABS 원문 |
| 증거 수준 | claimed — AX LABS 블로그의 고객 사례 소개, 제3자 검증 없음 | AX LABS 원문 |

## 성과와 수치

- 창고·물류 회사 사례: **450개 프로젝트를 단일 시스템으로 통합**
- **AI 비용 80% 이상 절감** (모델 계층화 라우팅 효과, 절감 전 기준액은 미공개)
- 수년간 이어지던 수기 재입력 업무 완전 제거
- 백그라운드 자동화 28개 상시 운영 — **인당 주당 60시간 수작업 제거**
- 모두 원문(AX LABS 블로그)의 자체 소개 수치로, 독립적 검증은 없음(claimed)

## 재현 가이드

- **난이도**: 상 (기술 난도보다 조직 전체 업무 매핑·데이터 모델 합의가 관건 — 여러 부서
  조율 필요)
- **준비물**: 현행 워크플로 목록, 기존 툴 사용 현황, 통합 데이터 모델 설계 인력, 소형·중형·
  프론티어 모델을 라우팅할 수 있는 오케스트레이션 레이어
- **핵심 단계**:
  1. 전사 워크플로를 먼저 지도화하고 기존 툴을 흡수/유지/폐기로 정리한다 (자동화 이전에
     정리부터)
  2. 여러 시스템의 데이터를 하나의 진실 원천으로 통합하는 데이터 모델을 설계하고, 이때
     조회 권한도 함께 정의한다
  3. 에이전트 투입 전에 시스템 간 연결(코어)부터 완성한다 — 자동화는 그다음
  4. 업무 성격(추출/분류 vs 요약 vs 판단)에 따라 모델 등급을 나눠 배치해 비용을 통제한다
  5. 초기 2~4주는 전건을 사람이 검토하며 정확도를 측정한 뒤 자동화 범위를 넓힌다

## 강의·AX 활용 포인트

- **AX**: "AI 도입 = 각 툴에 AI 버튼 추가"라는 흔한 오해를 바로잡는 반례로 쓰기 좋다.
  모델 계층화 라우팅으로 비용을 통제하는 접근은 [[databricks-ai-gateway-coding-cost-management]]
  (개발 도구 비용 관리)와 같은 원리를 전사 업무 영역으로 확장한 버전 — 두 사례를 나란히
  인용하면 "모델 라우팅이 코딩 툴에서 전사 운영체제로 일반화되는 흐름"을 보여줄 수 있다.
- **강의**: 6단계 구축 절차 자체가 AX 컨설팅·사내 AI 전환 프로젝트의 체크리스트로 바로
  쓸 수 있는 실무 프레임. "자동화 이전에 정리·데이터 모델부터"라는 원칙은 성급한 에이전트
  도입을 경계하는 사례로 유용.
- 정량 수치(80% 절감, 60시간 절감)는 AX LABS 블로그의 고객 사례 소개일 뿐 제3자 검증이
  없다는 점을 반드시 명시하고 인용할 것 — "실측"이 아니라 "주장" 수준으로 다뤄야 한다.
