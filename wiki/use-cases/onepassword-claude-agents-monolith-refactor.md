# 1Password — AI 에이전트로 수백만 라인 Go 모놀리식 코드 분해, 통한 것과 깨진 것

> **공식**: 자체 구축한 에이전틱 툴체인(코드 분석+추출 순서 결정+결정론적 실행 도구)을 활용해 대규모 모놀리식 서비스 분해(service extraction)를 수행 → 전체 20~30% 개선, 단 명세 밖 불변조건 문제는 에이전트가 표면화만 (실측)

## 무엇을 자동화했나

1Password가 자사 블로그에 공개한 사례. 수백만 라인 규모의 Go 모놀리식 서비스를 더 작은
서비스로 분해하는 리팩터링(service extraction) 작업에 AI 에이전트를 투입해 실전에서
무엇이 통했고 무엇이 깨졌는지를 상세히 기록했다.

## 어떻게 구성했나 (아키텍처)

- 자체 구축한 에이전틱 툴체인 — 코드 분석 + 서비스 추출 순서 결정 + 결정론적 실행 도구
  조합으로 구성.
- 에이전트가 수백만 라인 코드를 분석해 "어떤 순서로 서비스를 떼어내야 하는지" 추출 순서를
  제시.
- 작업 범위가 명확히 정의되고 경계가 있을 때는 에이전트가 빠르고 정확했지만, 명세 밖
  상황(예: UUID 컬럼 백필을 신규 행 삽입 코드 갱신보다 먼저 실행해 데이터를 조용히
  손실시키는 순서·불변조건 문제)을 만나면 **스스로 해결하려 하지 않고 표면화**하도록 설계.

## 성과와 수치

- **실측**: 전체적으로 **20~30% 개선**을 확인했으나, "면밀한 조정과 리뷰의 필요성을
  대체하지는 못했다"는 것이 저자의 결론.
- 명세 밖 데이터 손실 위험(순서·불변조건 문제)은 에이전트가 자체 해결하지 않고 표면화만
  했다는 점을 구체적으로 기록 — 실패 모드를 숨기지 않고 공개한 드문 사례.

## 재현 가이드

- **난이도**: 상
- **준비물**: 대규모 코드베이스 분석 도구, 서비스 추출 순서 결정 로직, 결정론적 실행
  도구(수작업이 아닌 스크립트화된 실행 단계)
- **핵심 단계**:
  1. 작업 범위를 명확히 정의하고 경계를 좁혀 에이전트에 위임할 부분을 한정
  2. 에이전트가 추출 순서를 제안하되, 실행은 결정론적 도구로 고정해 재현성 확보
  3. 명세 밖 상황(암묵적 불변조건, 데이터 정합성 문제)은 에이전트가 자동 해결하지 않고
     반드시 사람에게 표면화하도록 설계
  4. 개선율을 정기적으로 측정해 어디까지가 에이전트의 몫이고 어디부터 사람이 봐야 하는지
     구분

## 강의·AX 활용 포인트

- "에이전트에게 무엇을 맡기고 무엇을 사람이 계속 봐야 하는가"를 구체적 수치(20~30%)와
  실패 사례로 함께 보여주는 드문 자료 — 대규모 리팩터링 AX 파일럿 설계 시 기대치 조정에
  참고할 만하다.
- 에이전트가 "모르면 표면화" 하도록 설계한 원칙은 다른 자동화 사례(예:
  [[the-engineer-github-issue-to-pr]]의 승인 게이트)와 함께 안전장치 설계 강의에 활용 가능.
