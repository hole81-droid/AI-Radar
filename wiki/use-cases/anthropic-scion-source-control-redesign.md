> **공식**: Anthropic이 Claude(cli-pipeline)로 급증한 자율 코드 생성량을
> 감당하기 위해 git을 대체하는 사내 버전관리시스템 "Scion"을 구축 →
> 인프라 200배 축소·체크아웃 분→초 단위·CI CPU 용량 25% 확보

## 무엇을 자동화했나

Anthropic 내부에서 Claude를 이용한 자율 코드 생성이 늘면서 모노레포 일일
머지(merge) 건수가 2026년 5월 약 2,500건에서 9월 30,000건 이상으로
12배 폭증했다. git은 "오프라인에서도 동작"하는 분산 구조를 전제로
설계된 시스템이라, 에이전트가 끊임없이 커밋을 쏟아내는 "항시 온라인"
워크로드에서 구조적 병목이 됐다 — 압축된 워킹 카피가 25GB를 넘었고,
그대로 git fetch를 반복하면 하루 트래픽이 600PB를 넘는 수준까지 치솟았다.
Anthropic은 git을 무리하게 확장하는 대신 **자체 버전관리시스템 Scion을
처음부터 다시 설계**했다.

## 어떻게 구성했나 (아키텍처)

- **서버 중심 아키텍처**: git의 분산 모델과 달리 클라이언트가 상시
  온라인이라는 전제 위에서, 병합·리베이스·blame 같은 비용이 큰 연산을
  서버 쪽으로 이전했다.
- **체인지셋 기반 저장**: git의 트리 포인터 구조 대신 "첫 부모 기준으로
  바뀐 파일 목록 + 콘텐츠 주소 블롭 참조"로 커밋을 표현 — 락(lock) 없는
  증분 커밋이 가능해졌다.
- **파생 데이터 분리**: blame 인덱스·경로 히스토리·스킵 리스트 같은
  보조 구조를 체인지셋과 별도로 계산해, 클라이언트 쪽 변경 없이도
  서버 최적화를 계속 넣을 수 있게 설계.
- **3단 캐싱**: 로컬 데몬 → 지역 캐시 → 권위 서버로 이어지는 3계층
  캐시 구조로 최소한의 조정만으로 99% 이상의 캐시 적중률을 유지.
- 7인으로 구성된 팀이 **코드량이 10배로 늘어나는 와중에도 5개월 만에**
  전체 마이그레이션을 끝냈다.

## 성과와 수치

- **실측(measured)**: 인프라 footprint가 기존 git 미러링 체계 대비
  **200배 축소**됐고, 체크아웃 속도는 분 단위에서 **초 단위**(2자릿수 배)로
  빨라졌다. CI 용량은 **CPU 25%**를 추가로 확보했다.
- 타임라인 압박이 있었음에도 광범위한 테스트·퍼징·레이트리밋 설계까지
  갖췄다고 밝혔다 — "빠르게 만들었지만 품질을 희생하지 않았다"는 주장이나,
  이 부분은 자체 평가(claimed)에 가깝다.
- 일일 머지 건수 수치(2,500→30,000+)와 인프라 수치(200배·25GB·600PB)는
  모두 Anthropic 공식 엔지니어링 블로그 1차 발표.

## 재현 가이드

- **난이도**: 상 (git을 대체하는 VCS를 처음부터 구축하는 수준의 작업으로,
  대부분의 조직에는 "직접 재현"이 아니라 "병목 진단 프레임"으로서의
  가치가 크다)
- **준비물**: 에이전트가 생성하는 코드 변경량을 모니터링할 지표(일일
  머지 건수, 워킹 카피 크기, fetch 트래픽), 인프라 엔지니어링 팀
- **핵심 단계**:
  1. 에이전트 도입 후 커밋/머지 빈도가 어느 지점부터 기존 VCS의 설계
     전제(오프라인 우선)를 벗어나는지 측정
  2. 서버 중심 연산 이전이 가능한 지점(병합·리베이스·blame)부터
     점진적으로 분리
  3. 체인지셋/파생 데이터 분리처럼 "클라이언트 변경 없이 서버만
     최적화"할 수 있는 지점을 우선 설계
  4. 캐시 계층을 추가해 적중률을 높이고 마이그레이션 중 사용자 영향을
     최소화

## 강의·AX 활용 포인트

- **강의**: "에이전트 도입은 모델 교체가 아니라 인프라 재설계 문제"임을
  보여주는 가장 극적인 사례. 기존 [[anthropic-agentic-coding-ci-test-impact-analysis]]
  (CI 테스트 선택 서비스, 코드량 8배·CI job 25배 증가를 엔지니어 1명·3주로
  흡수)와 짝지어 가르치면, 같은 "에이전트 코드 폭증" 현상이 조직 내 서로
  다른 계층(CI ↔ 소스 컨트롤)에 동시에 압박을 준다는 것을 보여줄 수 있다.
- **AX**: 사내에 에이전트형 코딩 도구를 확대 적용하기 전에 "git 서버
  용량·네트워크 트래픽·CI 큐"가 얼마나 버틸 수 있는지 미리 가늠해보라는
  체크리스트로 쓸 수 있다. Anthropic처럼 자체 VCS를 새로 짤 필요는 없어도,
  "에이전트 스케일의 커밋 빈도"가 기존 도구의 설계 전제를 깰 수 있다는
  경고 신호로 유용하다.
