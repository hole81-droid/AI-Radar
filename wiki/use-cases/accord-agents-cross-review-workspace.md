> **공식**: [Claude Code + Codex 등 복수 코딩 에이전트]로 [공유 워크스페이스 기반 서브에이전트 교차검토]를 활용해 [여러 AI 코딩 에이전트 간 계획·PR 조율]을 수행 → [사람의 중계자 역할 제거 (주장)]

## 무엇을 자동화했나

Reddit r/AI_Agents에 개인 개발자가 공유한 사례. 여러 코딩 에이전트(Claude Code, Codex 등 서로 다른 공급자)를 동시에 쓰다 보니, 한 에이전트가 세운 계획이나 만든 PR을 사람이 직접 복사해 다른 에이전트에 붙여넣고, 둘의 의견이 갈리면 그 차이를 일일이 중재해야 했다. 이 "메신저 노릇"에 지친 저자가 바이브코딩으로 직접 만든 오픈소스 도구가 **Accord Agents**다. 여러 에이전트가 같은 태스크에 동시에 접근해 서로 질문·반박하며 계획과 변경사항에 합의하도록 만들어, 사람이 에이전트 사이를 오가며 내용을 전달하던 과정을 없애는 것이 목표다.

## 어떻게 구성했나 (아키텍처)

- 여러 코딩 에이전트(Claude Code, Codex 등)가 **공유 워크스페이스**에서 동일 태스크·동일 컨텍스트에 접근
- 에이전트들이 서로 질문·반박을 주고받으며 계획·변경사항에 대한 **교차검토(cross-review)** 를 수행 — 한 에이전트의 서브에이전트 역할을 다른 에이전트가 맡는 구조에 가까움
- 대화 전 과정이 사람에게 **반투명하게 노출**되어 필요 시 개입 가능 — 완전 자동화가 아니라 "사람이 중계자 역할만 빠지는" 설계
- 구체적인 통신 프로토콜(파일 기반인지, API/MCP 기반인지), 합의 판정 로직, 충돌 해결 알고리즘 등 내부 구현 세부는 원문 접근 실패로 미확인 (아래 출처 참고)

- **주장(claimed/anecdotal)**: 저자 본인 후기로 "에이전트 간 메신저 역할에서 벗어났다"는 정성적 평가만 있으며, 처리 시간 단축·품질 개선 등 측정된 수치는 없다.

## 재현 가이드

- **난이도**: 상 (직접 도구를 만들거나 오픈소스를 구성해야 하는 실험적 워크플로우 — 원문에서 구체 실행 단계 확인 실패)
- **준비물**: Claude Code, Codex 등 2개 이상의 코딩 에이전트 계정/CLI, 공유 워크스페이스 구성 (원문 세부 미확인)
- **핵심 단계**: (원문 접근 실패로 추정 불가 — 뉴스레터 요약 기준)
  1. 동일 태스크를 여러 에이전트가 접근 가능한 공유 워크스페이스에 배치
  2. 각 에이전트가 계획을 제안하면 다른 에이전트가 질문·반박하도록 유도
  3. 합의된 계획만 실제 변경(PR)으로 반영
  4. 사람은 반투명 로그를 관찰하며 필요할 때만 개입

## 강의·AX 활용 포인트

- **강의**: 멀티 에이전트 오케스트레이션의 한 패턴("사람이 중계자가 아니라 감독자로 물러나는 설계")으로 소개할 수 있음. 단 측정 수치가 없어 "아이디어 사례"로만 다루고, 실측된 [[cowork-7-business-use-cases]] 같은 사례와 구분해 제시할 것.
- **AX**: 여러 벤더의 에이전트를 동시에 쓰는 조직에서 조율 비용이 실제 병목이 될 수 있음을 보여주는 커뮤니티 신호. 다만 evidence가 anecdotal이므로 벤치마크 근거보다는 "주목할 만한 문제의식" 정도로 인용해야 함.
