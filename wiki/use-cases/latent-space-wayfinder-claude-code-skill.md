# /wayfinder — "기획의 안개"를 다루는 Claude Code 스킬

> **공식**: Claude Code Skill `/wayfinder`(skills)를 활용해 목표가 불분명한 프로젝트의
> 기획 단계를 맵·티켓·세션 3단 계층 구조로 관리 → 컨텍스트 윈도우 제약 없이 프로토타입·
> 리서치·스펙 작업을 하위 세션에 위임(정성적 사례, 벤치마크 수치 없음)

## 무엇을 자동화했나

Matt Pocock(개발자·교육자)이 만들고 Latent Space가 소개한 Claude Code 스킬. 최종 형태가
불분명한 그린필드 프로젝트에서 "무엇을 해야 할지조차 명확하지 않은" 기획 단계 자체를
다루기 위해 설계됐다. 기존 코딩 에이전트 워크플로는 매 변경마다 완전한 문장으로 지시해야
하고 프롬프트가 세션이 끝나면 버려지는 문제, 프로젝트가 커질수록 기획 자체가 컨텍스트
윈도우 한계에 부딪히는 문제의식에서 출발했다.

## 어떻게 구성했나 (아키텍처)

3계층 구조:
- **맵(Map)**: 이전 결정·컨텍스트를 담는 중앙 문서
- **티켓(Ticket)**: 개별 세션에 줄 구체적 과제 할당
- **세션(Session)**: 실제 작업 실행

"세션이 다른 세션을 관리할 수 있다면?"이라는 아이디어에서 출발해 부모-자식 세션 간 위임
구조를 만들었다. 자식 세션은 프로젝트 전체 개요와 좁은 과제를 함께 받아, 토큰 제약 없이
작업할 수 있다. 티켓 종류는 4가지 — grilling(질문으로 요구사항을 좁히는 대화형 티켓)·
prototype·research·task.

## 성과와 수치

- Pocock 본인이 **20년 치 콘텐츠가 쌓인 개인 웹사이트 재아키텍처링**에 적용해 검증
- 코스 기획 등 비(非)엔지니어링 영역에도 적용 가능하다고 주장
- "AFK(자리 비움) 에이전트에게 상세 사양을 던져두고 밤새 돌리는" 워크플로가 가능해졌다는
  주장 — 전부 anecdotal, 독립 검증·정량 지표 없음

## 재현 가이드

- **난이도**: 중 (기술 구현보다 "맵 문서를 최신 상태로 유지하는 습관"이 관건)
- **준비물**: Claude Code, 계층형 문서(맵) 관리 습관 — 공개 저장소·설치 명령은 원문에
  명시되지 않아 재현 전 원문 재확인 필요
- **핵심 단계**:
  1. 프로젝트 전체 컨텍스트를 담는 맵 문서부터 만든다
  2. 요구사항이 불명확하면 먼저 grilling 티켓으로 질문을 통해 좁힌다
  3. 프로토타입·리서치·실행 과제를 티켓 단위로 쪼개 하위 세션에 위임한다
  4. 하위 세션에는 전체 개요 + 좁은 과제만 전달해 토큰을 아낀다

## 강의·AX 활용 포인트

- **강의**: [[loop-engineering]](계획·탐색·수정·검증 반복 시스템)의 연장선으로, 단일
  프롬프트가 아니라 "기획 단계 자체"를 계층적 시스템으로 다루는 최신 방법론 사례. 구루
  1차 채널(Latent Space) 발 소식이라 신뢰도는 있으나 검증된 벤치마크가 없는 개인 도구
  수준임을 함께 밝혀야 한다.
- **AX**: "요구사항이 불분명한 프로젝트"에서 에이전트를 어떻게 투입할지 고민하는 팀에게
  구조적 접근(맵·티켓·세션)을 소개하는 참고 사례로 유용.
