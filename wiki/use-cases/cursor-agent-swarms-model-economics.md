# Cursor "Agent Swarms and the New Model Economics" — 플래너·워커 계층형 에이전트 스웜으로 비용 8배 절감

> **공식**: Cursor로 플래너(프론티어 모델)-워커(저가 모델) 계층형 에이전트 스웜(subagents+cli-pipeline)을
> 활용해 SQLite를 Rust로 처음부터 재구현하는 대형 코딩 벤치마크를 수행 → 비용 $10,565→$1,339(8배↓),
> 머지 충돌 70,000+건→1,000건 미만 (Cursor 자체 실측)

## 무엇을 자동화했나

Cursor가 2026-07 자체 블로그에 공개한 연구. 여러 AI 에이전트가 동시에 협업해 대형 코딩
작업을 수행하는 "에이전트 스웜" 아키텍처를 개선하고, 구버전 시스템과 신버전을 SQLite를
Rust로 처음부터 재구현하는 동일한 대형 벤치마크로 직접 비교했다. 단일 에이전트로는
비현실적인 규모의 작업을 다수 에이전트 동시 분업으로 완수하는 사례다.

## 어떻게 구성했나 (아키텍처)

- **계층형 트리 분해**: 플래너 에이전트(프론티어 모델)가 목표를 작업 트리로 쪼개 단계적으로
  실행 가능한 작업으로 낮추고, 워커 에이전트(대개 더 빠르고 저렴한 모델)가 구체적인 조각을 실행.
- **커스텀 버전관리 시스템**: 초당 1,000커밋 처리(구버전 초당 17커밋 대비 대폭 개선).
- **설계문서 참조**: 여러 에이전트가 서로 충돌하는 아키텍처 결정을 내리지 않도록 공유 설계 문서를 참조.
- **중립 머지 충돌 해결 에이전트**: 파일 충돌을 공정하게 처리하는 전담 에이전트.
- **파일 분해**: "메가파일"이 병목이 되는 것을 방지.
- **다중 리뷰 렌즈(stacked review lenses)**: 여러 독립 리뷰 에이전트로 교차 검증.
- **Field Guide**: 에이전트가 스스로 축적한 공유 컨텍스트를 세션 시작 시 자동 주입.

## 벤치마크 데이터

| 항목 | 값 |
|---|---|
| 모델 | 플래너: 프론티어 모델(Opus 등) / 워커: Composer, GPT-5.5 등 저가 모델 — 여러 조합 비교 |
| 비용 | 구성별 $1,339(Opus+Composer 하이브리드) ~ $10,565(GPT-5.5 단독) |
| 권한 | 미확인 |
| 성숙도 | pilot (Cursor 사내 연구 벤치마크 — 고객 대상 정식 기능화 여부는 명시 안 됨) |

## 성과와 수치

- **실측(measured)**: 머지 충돌 구버전 70,000건 이상 → 신버전 1,000건 미만.
- **실측**: 동일 기능 구현에 필요한 코드량 — 구버전 19,013줄 vs Opus/Composer 하이브리드 4,645줄
  (약 4배 압축, 불필요한 코드 최소화 효과 시사).
- **실측**: 완료 비용 — 구성에 따라 $1,339(Opus+Composer 하이브리드)부터 $10,565(GPT-5.5 단독)까지
  최대 8배 차이.
- 핵심 결론: "대형 작업 중 진짜 프론티어급 지능이 필요한 순간은 소수" — 플래너에만 고성능 모델을
  쓰고 실행은 저가 모델에 맡기는 하이브리드 구성이 품질 저하 없이 비용을 대폭 낮췄다.

## 재현 가이드

- **난이도**: 상 (커스텀 버전관리·병합 충돌 해결·리뷰 렌즈 등 인프라를 직접 구축해야 재현 가능)
- **준비물**: 다수 에이전트를 동시에 띄울 수 있는 오케스트레이션 환경, 플래너용 프론티어 모델 +
  워커용 저가 모델 API 접근권, 파일 충돌 자동 해결 로직
- **핵심 단계**:
  1. 목표를 플래너 에이전트가 작업 트리로 분해
  2. 저가 워커 에이전트에게 개별 작업 실행을 위임 (프론티어 모델은 계획에만 사용)
  3. 공유 설계 문서·Field Guide로 에이전트 간 컨텍스트 정합성 유지
  4. 전담 충돌 해결 에이전트 + 다중 리뷰 렌즈로 병합 안정성 확보
  5. 파일을 잘게 쪼개 "메가파일" 병목 방지

## 강의·AX 활용 포인트

- **강의**: "멀티 에이전트 오케스트레이션에서 비용을 결정하는 것은 병렬 수가 아니라 컨텍스트
  효율과 조율 메커니즘"이라는 핵심 통찰을 실물 벤치마크 수치로 가르치기 좋은 사례.
  플래너-워커 계층 구조는 다른 에이전트 프레임워크(Claude Code subagents 등)에도 그대로 응용 가능.
- **AX**: 대형 개발 프로젝트에 에이전트 스웜을 투입할 때 "전부 프론티어 모델"이 아니라
  역할별 모델 티어링으로 비용을 8배 가까이 낮출 수 있다는 구체적 근거. 단, 충돌 해결·리뷰
  인프라 구축 비용은 별도로 감안해야 한다.
