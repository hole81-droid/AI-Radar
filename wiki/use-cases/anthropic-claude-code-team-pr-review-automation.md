> **공식**: Claude Code로 subagents+skills를 활용해 PR 코드리뷰·위험기반 인간 승인을 수행 → 되돌리기율 40%+↓, 1회 통과율 65%→78%

## 무엇을 자동화했나

Anthropic의 Claude Code 팀 자체가 겪은 문제다. 에이전트가 코드의 약 90%를 작성하게
되면서 일일 PR이 2026년 5월 2,500건에서 9월 30,000건 이상으로 폭증했다. 모든 diff를
인간이 한 줄씩 읽는 전통적 코드리뷰는 물리적으로 불가능해졌다. 해법은 "인간 리뷰를
없애는 것"이 아니라 **인간의 주의력을 고가치 판단에만 쓰도록 리뷰 과정 전체를
재설계**하는 것이었다.

## 어떻게 구성했나 (아키텍처)

7단계 파이프라인:

1. **PR 생성 전 검증** — 에이전트가 테스트·빌드·린터를 직접 실행, 서브에이전트가
   "신선한 컨텍스트"로 diff를 재검토, 내부 Skill이 버그 탐색·코드 단순화 수행
2. **모든 PR에 자동 AI 리뷰** — Claude가 diff를 저장소 컨텍스트와 대조해 읽고, 여러
   에이전트가 병렬로 버그를 탐색한 뒤 별도 에이전트가 발견사항에 투표(검증된 것만
   심각도순 코멘트로 노출)
3. 자동 보안 리뷰
4. 린트·타입·테스트·빌드 체크
5. **위험도 기반 인간 승인** — `CLAUDE.md`(프로젝트 컨벤션)와 `REVIEW.md`(코드
   오너가 정의하는 "실패"의 기준)를 근거로 저위험(문서·플래그)은 인간 승인 0명,
   중위험(제품 변경)은 1명, 고위험(과금·자동업데이터)은 2명
6. 머지 큐 재검증
7. 피처 플래그·단계적 롤아웃·빠른 롤백

## 성과와 수치 (2026년 6월~9월, 실측)

- 머지되는 PR 2배 이상 증가
- 되돌리기(revert)율 40% 이상 감소
- 실질 리뷰 코멘트를 받는 내부 PR 비율: 16% → 54%
- 1회 리뷰-수정 사이클 후 통과하는 PR: 65% → 78%
- 통과까지 평균 리뷰 라운드: 2.08 → 1.32

인간의 시간은 "모든 diff를 읽는 것"에서 아키텍처 선택, 위험한 코드의 소유권, 기능이
존재해야 하는지 여부 같은 전략적 질문으로 이동했다고 설명한다.

## 재현 가이드 (난이도: 중)

준비물: 코딩 에이전트(서브에이전트 지원), 프로젝트별 컨벤션 문서(`CLAUDE.md` 유사물),
코드 영역별 "실패 기준" 문서(`REVIEW.md` 유사물), 변경 위험도를 분류할 기준.

1. PR 생성 전에 에이전트 스스로 테스트·빌드·린트를 통과시키는 게이트를 건다.
2. 모든 PR에 자동 AI 리뷰를 붙이되, "여러 에이전트가 찾고 별도 에이전트가 투표"해
   거짓양성을 줄인다.
3. 변경 영역을 위험도로 분류하고, 위험도별로 필요한 인간 승인자 수를 다르게 정한다.
4. 보안 리뷰·린트·테스트를 별도 자동 게이트로 분리해 인간 승인 전에 걸러낸다.
5. 머지 후에도 피처 플래그·단계적 롤아웃으로 실패를 빠르게 되돌릴 수 있게 한다.

## 강의·AX 활용 포인트

- "AI가 코드를 더 많이 쓴다"는 것과 "조직이 더 많은 소프트웨어를 출시한다"는 것은
  다른 문제라는 것을 보여주는 가장 구체적인 반례다. 같은 날 발견된
  [[2026-10-12-harvard-ai-coding-agents-review-bottleneck]](Harvard 연구 — 700개+
  기업에서 코드량은 늘었지만 산출물은 그대로, 원인은 리뷰 병목)와 정반대 결론을
  대조하면 강의 소재로 강력하다 — **같은 병목을 만났을 때 "위험 기반 자동화로
  뚫은 조직"과 "그대로 막힌 대다수 조직"의 차이**.
- AX 관점에서는 "코드리뷰 자동화 = 품질 포기"가 아니라 "고위험 변경에만 인간을
  집중시키는 재배치"라는 점을 강조할 수 있다.
