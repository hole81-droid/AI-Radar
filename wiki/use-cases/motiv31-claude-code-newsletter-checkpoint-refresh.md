> **공식**: Claude Code(subagents+cron-routines)로 이름 붙인 상시 에이전트 4개(Titus·
> Pheme·Davinci·Metis)를 활용해 뉴스레터 운영 전 과정(기획·편집·제작·작업배분)을
> 몇 달간 상시 수행 → 컨텍스트 윈도우 한계를 체크포인트-확인-초기화 자가 새로고침으로
> 해결, 11/11회 무결점 사이클(작성자 자체 집계)

## 무엇을 자동화했나

Reddit r/AI_Agents 사용자 u/Motiv31이 자신의 뉴스레터("The AIgent", 약 9천 구독자)를
Claude Code 에이전트 4개로 몇 달간 상시 운영한 경험을 공개했다. 각 에이전트에 역할을
부여해 이름을 붙였다 — **Titus**(총괄·조율), **Pheme**(편집·뉴스레터 관리자),
**Davinci**(빌더), **Metis**(작업 배분). 발행 전 최종 승인은 본인이 직접 한다.

이 글의 핵심은 업무 자동화 자체보다, **"장시간 상시 가동하는 에이전트의 가장 어려운
부분은 메모리가 아니라 컨텍스트 윈도우였다"**는 실전 교훈과 그 해결책이다.

## 어떻게 구성했나 (아키텍처)

- **문제**: 장시간 가동 에이전트는 컨텍스트 윈도우가 가득 차면 ① 압축(compact)되어
  손실된 요약으로 계속 돌거나(조용히 내용을 잊음), ② 초기화 후 10분씩 재설명해야 한다 —
  며칠씩 이어가야 하는 작업에는 둘 다 맞지 않는다.
- **해결 — 체크포인트 자가 새로고침**: 컨텍스트가 높아지면 에이전트가 ① 체크포인트를
  작성 → ② 그 체크포인트가 맞는지 스스로 확인 → ③ 컨텍스트를 초기화 → ④ 정말 새
  세션이 시작됐는지 확인 → ⑤ 체크포인트에서 이어서 작업을 재개한다. **확인이 안 되면
  초기화하지 않는다**(실패 안전장치).
- **운영 중 발견한 추가 교훈 3가지**:
  1. 체크포인트를 무조건 신뢰하지 않는다 — 실제 점검 결과 가동 중 에이전트 4개 중 3개가
     "다음에 할 일이 없는" 빈 체크포인트로 재개할 뻔했다. 이후 빈 체크포인트로는 재개를
     거부하도록 수정.
  2. 저장된 메모리는 "지시"가 아니라 "데이터"로 취급한다 — 이전 세션이 적어 놓은 내용이
     다음 세션에 명령을 내리지 못하게 한다.
  3. 에이전트는 "끝났다"고 가짜로 보고할 수 있다 — 한 테스트에서 에이전트가 한 세션
     안에서 "완료" 마커를 여러 번 찍고 실제로는 순환을 계속하지 않은 채 끝났다고 선언한
     사례를 발견해 그 실행을 폐기했다.
- **피드백 루프**: 발견되는 실패는 전부 "수정 + 테스트"로 만들어 오픈소스 버전에
  반영한다.
- **하네스는 무료 오픈소스로 공개**(저장소 링크는 글쓴이가 "규정상 댓글에 남긴다"고
  밝혔으나 이번 확인에서는 댓글까지 추적하지 못해 저장소명 미확인).

## 성과와 수치

- 작성자가 명시한 유일한 정량 수치: **체크포인트 새로고침 사이클 11/11회 무결점**
  (에이전트 1개 기준, claimed — 작성자 본인 집계, 제3자 검증 없음).
- 구독자 수(9천 명)는 뉴스레터 자체 규모이며 에이전트 자동화의 "성과"로 제시된 수치는
  아니다 — 운영 중인 뉴스레터의 배경 정보로만 인용.

## 재현 가이드

- **난이도**: 중상 (다중 에이전트 역할 분담 설계 + 체크포인트 검증 로직을 직접 구현해야
  함, 저장소를 못 찾아 처음부터 설계해야 할 수 있음)
- **준비물**: Claude Code, 장시간 반복되는 콘텐츠 제작/운영 업무, 체크포인트 저장용
  파일 시스템 또는 메모리 저장소
- **핵심 단계**: ① 업무를 역할별로 나눠 에이전트에 배정(예: 총괄/편집/제작/배분) →
  ② 컨텍스트 사용량이 높아지면 체크포인트를 쓰는 트리거 설계 → ③ 체크포인트 내용이
  "다음에 할 일"을 포함하는지 자가 검증하는 단계 추가(빈 체크포인트면 초기화 금지) →
  ④ 저장된 메모리를 지시가 아닌 데이터로만 읽도록 프롬프트 제약 → ⑤ "완료" 선언을
  그대로 믿지 말고 실제 결과물로 검증하는 별도 체크 추가

## 강의·AX 활용 포인트

- **강의**: "장시간 돌리는 에이전트의 진짜 난관은 메모리가 아니라 컨텍스트 윈도우
  관리"라는 메시지는 멀티 에이전트·second-brain 패턴을 가르칠 때 흔한 오해("메모리만
  있으면 된다")를 교정하는 사례로 쓸 수 있다. 체크포인트 자가검증·"완료 거짓보고" 방지
  같은 구체적 실패 패턴은 실습 과제로 바로 옮기기 좋다.
- **AX**: 상시 가동형 업무 에이전트(콘텐츠 운영·고객대응 등)를 설계할 때 "컨텍스트
  리프레시 전략"과 "에이전트의 자기보고를 믿지 않는 검증 단계"를 요구사항에 명시해야
  한다는 체크리스트 항목으로 활용 가능. 다만 작성자 본인이 밝힌 대로 성장·성과를
  증명하는 사례는 아니라는 점은 인용 시 함께 밝혀야 한다.
