# OpenAI × Thrive Holdings — Codex 기반 자가개선형 세무 AI, 정확도 97%·처리량 50%↑

> **공식**: OpenAI Codex를 Thrive Holdings 세무 소프트웨어에 통합해 회계사 수정 이력 기반 자가개선 루프를 활용해 미국 세무 신고서(1040·1041) 준비를 수행 → 정확도 97%, 처리량 50% 증가, 회계사 1인당 180시간→15시간 (실측)

## 무엇을 자동화했나

미국 개인·신탁 세무 신고서(1040·1041) 준비를 돕는 AI 시스템을 Codex 기반으로 구축해
Crete Professional Alliance 소속 30여 개 회계법인에서 실제 세무 시즌에 투입, 총 7000건을
처리했다.

## 어떻게 구성했나 (아키텍처)

- 회계사들이 실제로 고친 수정 이력과 과거 신고 전체 트레이스를 시스템에 축적.
- Codex가 이 데이터를 근거로 자주 발생하는 오류 패턴을 찾아 **소프트웨어 코드 자체를
  스스로 수정·개선**하는 루프를 반복 — 사용할수록 정확도가 올라가는 자가개선 설계.
- OpenAI 엔지니어와 Thrive 팀이 6개월간 공동 개발.

## 벤치마크 데이터

| 항목 | 값 |
|---|---|
| 모델 | OpenAI Codex |
| 비용 | 미확인 |
| 권한 | 미확인 |
| 성숙도 | production (실제 세무 시즌, 30여 회계법인·7000건 처리) |

## 성과와 수치

- **실측**: 최종 초안 정확도 **97%**(수정 없이), 신고서 1건당 준비 시간 **1/3 절감**,
  전체 처리량 **50% 증가**.
- 한 회계사는 작년 세무 시즌에 **180시간**을 썼던 업무를 올해 **15시간**으로 줄이고,
  남는 시간을 고객 상담과 신규 고객 확보에 썼다.
- 6개월 공동 개발 기간, 30여 회계법인·7000건 처리라는 규모도 구체적으로 확인됨.

## 재현 가이드

- **난이도**: 상 (벤더와의 6개월 공동 개발 필요, 자체 데이터 축적 체계 필수)
- **준비물**: Codex(또는 동급 코딩 에이전트), 회계사 수정 이력 데이터, 과거 처리 트레이스
  축적 체계
- **핵심 단계**:
  1. 반복 업무(세무 신고서 초안)의 과거 처리 이력과 사람이 고친 수정 내역을 데이터로 축적
  2. 자주 발생하는 오류 패턴을 에이전트가 스스로 찾아 소프트웨어 코드를 개선하는 루프 설계
  3. 벤더(모델 제공사)와 실무 팀이 장기간(6개월) 공동 개발해 도메인 지식을 반영
  4. 정확도·처리시간·처리량을 정기적으로 측정해 자가개선 효과를 검증

## 강의·AX 활용 포인트

- "AI가 코드를 스스로 고치며 개선한다"는 자가개선 루프의 **실측 사례**라서 AX 강의
  소재로 특히 강력하다 — 모델·비용은 미확인이지만 성과 지표는 4개 모두(정확도·시간·
  처리량·개인 사례) 구체적으로 확인된다.
- "180시간→15시간"이라는 개인 사례 수치는 ROI를 경영진에게 설명할 때 가장 직관적인
  근거로 쓸 수 있다.
- 전문직(세무·회계) 반복 업무 자동화의 대표 사례로, [[jocoding-ax-series-pwc-samil]](HR
  전형 자동화)과 함께 "전문직 업무의 AI 자동화 성숙도" 비교 강의에 활용 가능.
