# Claude Code는 "메모리 파일"이 아니라 "대화 기록"으로 스스로 개선됐다

> **공식**: Claude Code(second-brain 방식 메모리+대화기록 축적)로 시뮬레이션 비즈니스
> 업무 처리 능력의 세션 중 자가 개선을 실험 → held-out 작업 성공률 34%→48%(+14%p),
> 개선의 원천은 메모리 파일이 아니라 대화 기록 자체(실측)

## 무엇을 자동화했나

연구자 Andrew Jesson이 Claude Code(Opus 5, xhigh effort)에게 스프레드시트·CRM 레코드·
이메일·티케팅 등에서 업무를 끌어오는 시뮬레이션 "비즈니스 워크플로 서버"를 붙이고,
에이전트가 작업을 수행하며 실제로 "배우는지", 배운다면 무엇이 학습을 이끄는지 측정했다.
목적은 업무 자동화 자체가 아니라 **에이전트 자가개선의 메커니즘을 실측으로 해부**하는 것.

## 어떻게 구성했나 (아키텍처)

- **에이전트 구성**: 메모리 파일 기록·코드 실행·서브에이전트·웹 검색 권한을 모두 부여했으나,
  실제로는 서브에이전트·코드실행·웹검색은 거의 사용되지 않았고 메모리 파일 작성과 대화
  기록 누적이 주요 경로였다.
- **메모리 구조**: 84회의 메모리 쓰기로 상호 링크된 지식베이스(디렉터리형 노트)를 구축 —
  일종의 "세컨드 브레인" 패턴.
- **대화 기반 학습**: 세션이 길어지며 압축(compaction) 요약이 반복 발생 — 이전 작업의
  실행 흔적과 압축 요약이 대화 컨텍스트 안에 누적됐다.
- **비교 설계**: held-out(학습에 쓰이지 않은) 작업 세트로 성공률을 반복 측정해, "메모리
  파일 유무"와 "대화 기록 유무"가 각각 성능에 기여하는 정도를 통계적으로 분리했다.

## 벤치마크 데이터

| 항목 | 값 |
|---|---|
| 모델 | Claude Opus 5, effort: xhigh |
| 비용 | 미확인 |
| 권한 | 미확인 (메모리 파일 기록, 코드 실행, 서브에이전트, 웹 검색 권한 부여됐으나 후자 3개는 거의 미사용) |
| 성숙도 | prototype — 개인 연구자의 통제된 실험, 프로덕션 배포 아님 |

## 성과와 수치 (실측)

- **전체 개선**: held-out 작업 성공률이 **34% → 48%**로 상승(+14 퍼센트포인트).
- **대화 기록의 기여**: 베이스라인 대비 **+9.9%p** [90% CI: +5.9, +13.8] — 통계적으로
  뚜렷한 효과.
- **메모리 파일의 기여**: **+1.7%p** [90% CI: −5.3, +8.6] — 신뢰구간이 0을 포함해
  통계적으로 유의하지 않음. 에이전트가 열심히 메모리를 쓰고 유지했음에도 그 자체는 성능
  개선에 거의 기여하지 않았다는 뜻.
- **압축 요약의 효율**: 세션 압축 요약이 원본 대화 토큰의 **1% 미만 비용**으로 개선 효과의
  대부분을 보존했다.
- **사고(thought) 내용의 기여**: 런이 진행될수록 "사고 과정" 자체가 성능에 기여하는 비중은
  점차 줄어들어 마지막 구간에서는 거의 무의미한 수준으로 떨어졌다.

## 재현 가이드

- **난이도**: 상 (통제된 A/B 비교 실험 설계, 시뮬레이션 업무 서버 구축, 통계 검정 필요)
- **준비물**: Claude Code(Opus 5급 모델), 반복 실행 가능한 시뮬레이션 업무 벤치마크,
  held-out 평가셋
- **핵심 단계**:
  1. 스프레드시트·CRM·이메일·티케팅을 모사하는 업무 서버를 구성해 에이전트에 반복 작업을
     부여한다.
  2. 메모리 파일 기록 권한을 켠 조건/끈 조건, 긴 대화 유지 조건/압축·초기화 조건을 나눠
     같은 held-out 작업 세트로 성공률을 측정한다.
  3. 신뢰구간을 포함해 각 요인(메모리 vs 대화)의 독립 기여도를 통계적으로 분리한다.
  4. 압축 요약이 원본 대비 얼마나 적은 토큰으로 개선 효과를 보존하는지 별도로 측정한다.

## 강의·AX 활용 포인트

- **강의**: "에이전트에게 메모리 파일을 주면 알아서 똑똑해진다"는 통념을 실측으로 반박하는
  드문 사례 — 컨텍스트 엔지니어링 수업에서 "왜 대화 기록(또는 그 압축본)이 명시적 메모리
  파일보다 더 강력한 학습 신호가 되는가"를 가르칠 때 1차 자료로 쓸 수 있다.
- **AX**: 사내에서 에이전트에 "학습 메모리" 기능을 도입할 때, 메모리 파일 구조 설계에
  공을 들이기 전에 먼저 "긴 세션·압축 요약을 유지하는 것"만으로 얼마나 개선되는지부터
  실측하는 것이 비용 대비 효율적일 수 있다는 시사점. [[ai-agent-profiler-claude-code-cost-benchmark]]와
  마찬가지로 "AI 도구에 대한 직관을 실측으로 검증하라"는 이 위키의 반복 주제와 맞닿는다.
