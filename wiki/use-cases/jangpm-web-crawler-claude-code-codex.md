> **공식**: Claude Code(또는 Codex·ChatGPT Work)로 오픈소스 웹 크롤링 에이전트
> "web-crawler"(browser-agent+cli-pipeline)를 활용해 URL+한 줄 설명만으로 웹사이트
> 데이터 수집 전 과정(정찰→수집코드 생성→검증→엑셀 정리)을 자동화 → 나라장터 입찰공고
> 140건·금감원 PDF 107개·쿠팡 리뷰 1,000건 등 실전 검증(비개발자도 실행 가능)

## 무엇을 자동화했나

"일잘러 장피엠"(YouTube) 채널 운영자가 개발자가 아닌 직장인을 대상으로, 입찰 공고·채용
공고·리뷰·부동산 매물처럼 반복적으로 수작업 복사·붙여넣기 하던 웹 데이터 수집 업무를
자동화하는 오픈소스 에이전트 "web-crawler"를 무료 공개했다. 사용자는 URL을 붙여넣고
"무엇을 모을지" 한 줄로 설명하기만 하면 되고, 나머지(사이트 구조 정찰·수집 전략 선택·
수집 코드 작성·엑셀 저장)는 에이전트가 전담한다. 목록형이 아닌 사이트, 상세페이지 진입이
필요한 수집, 첨부 PDF 다운로드, 로그인이 필요한 사이트(네이버 카페·인스타그램), 봇 차단이
강한 사이트(쿠팡)까지 실전 시연한다.

## 어떻게 구성했나 (아키텍처)

- **호환 에이전트**: Claude Code 또는 Codex(ChatGPT Work 포함)에서 셋팅해 구동 — 도구
  자체가 아니라 그 위에서 도는 워크플로/에이전트 구성 방식.
- **기술 스택**: Python 3.10+ + [Scrapling](https://github.com/) 계열 수집 프레임워크,
  Node.js 18+ 기반 `agent-browser`(사이트 구조 정찰), Playwright 경유 Chromium, 결과는
  `openpyxl`로 엑셀 저장.
- **워크플로 5단계**: ① 입력 파싱(URL+수집 항목) → ② 정찰(사이트 구조·API·페이지네이션
  탐색) → ③ 수집 전략 선택(순수 HTTP/세션 유지/동적 렌더링/안티봇 대응 중 사이트에 맞는
  방식) → ④ 수집 스크립트 생성·실행 → ⑤ 데이터 검증 후 향후 재사용을 위한 "도메인
  프로필" 저장.
- **코드-LLM 역할 분담**: "정찰하고, 전략을 짜고, 코드를 씁니다" — 판단(어떤 전략을 쓸지)은
  LLM이, 실행(실제 크롤링)은 결정론적으로 생성된 코드가 맡는 하이브리드 구조. 순정
  Claude Code로 직접 크롤링을 시키는 것과 결과를 비교해서 보여준다.
- **안전장치**: 자동 접근제한 우회(CAPTCHA·WAF) 시 사용자 확인 필수, robots.txt 확인+
  속도 제한, PII 패턴 탐지 시 경고, CAPTCHA 자동 풀이·자격증명 저장 금지, 검증되지 않은
  방법의 도메인 프로필 배포는 화이트리스트로 차단.
- **재사용·확장**: 루틴·예약 기능으로 매일 자동 수집하고 결과를 슬랙·메일로 받는 구성,
  그리고 이 에이전트를 각자 업무에 맞게 "개량"하는 세 가지 방법을 영상 후반부에서 다룬다.
- **저장소**: [github.com/byungjunjang/web-crawler](https://github.com/byungjunjang/web-crawler),
  MIT 라이선스, 14개 사전 설정 도메인 프로필 포함. `ACCEPTABLE_USE.md`로 법적 사용 범위를
  안내(자동 필터링이 아니라 사용자 책임 강조).

## 성과와 수치

- 제작자 자기 보고(claimed, 영상 시연 기준): 나라장터 입찰 공고 **140건**, 금융감독원
  보도자료+첨부 PDF **107개**, 쿠팡 리뷰 **1,000건**을 실제로 수집. 로그인이 필요한 네이버
  카페·인스타그램에서도 수집 성공을 시연.
- 제3자 검증이나 처리 시간·비용 절감 등 비교 수치는 없다 — 영상 속 시연 결과이지 독립
  감사된 벤치마크는 아니다.
- GitHub 저장소 star·fork 등 확산 지표는 수집 시점 스냅샷이 아직 없어 이번 기록에는
  포함하지 않았다.

## 재현 가이드 (난이도: 중)

1. Claude Code 또는 Codex(혹은 ChatGPT Work) 환경을 준비하고, Python 3.10+·Node.js 18+를
   설치한다(Windows는 `scripts\setup.ps1`, macOS/Linux는 `scripts/bootstrap.py` 원커맨드
   설치 스크립트 제공).
2. `github.com/byungjunjang/web-crawler`를 clone해 에이전트를 로컬에 셋팅한다.
3. 수집하려는 URL과 "무엇을 모을지"를 한 줄 자연어로 에이전트에 지시한다 — 에이전트가
   사이트를 정찰하고 알맞은 수집 전략(정적/세션/동적/안티봇 대응)을 스스로 고른다.
4. 목록형이 아닌 사이트(상세페이지 진입), 첨부파일 다운로드, 로그인 필요 사이트 등
   난이도가 높은 케이스는 영상의 6개 실전 예시(나라장터·금감원·원티드·네이버뉴스·
   네이버부동산·쿠팡)를 참고해 단계적으로 확장한다.
5. (옵션) 반복 수집이 필요하면 루틴·예약 기능으로 매일 자동 실행하고 결과를 슬랙·메일로
   받도록 구성한다.
6. 수집 전 `ACCEPTABLE_USE.md`를 검토해 대상 사이트의 이용약관·robots.txt·개인정보 수집
   여부를 법적으로 확인한다(영상 후반부에 크롤링 적법성 판단 6가지 기준을 별도로 다룸).

## 강의·AX 활용 포인트

- "코드는 결정론적으로 실행하고 판단만 LLM에 맡긴다"는 하이브리드 설계는 이 위키가 반복
  확인해온 안정적 패턴이다 — [[draw-your-font-claude-code-skill]](AI 인식+결정론적 CLI)와
  같은 원리로 나란히 강의할 수 있다.
- 비개발자가 GitHub clone부터 실행까지 따라올 수 있도록 눈높이를 맞춘 구성이라 "AI 도구를
  쓰는 단계에서 내 업무에 맞게 고쳐 쓰는 단계로" 넘어가는 강의 소재로 적합.
- AX 관점에서는 입찰·채용·규제 동향처럼 반복적으로 웹을 확인해야 하는 직군(총무·구매·
  마케팅·법무)에 재현 난이도 "중"으로 바로 시도해볼 만한 무료 오픈소스 사례 — 다만 로그인
  필요 사이트·개인정보 수집은 이용약관·법적 리스크를 먼저 검토해야 한다는 점을 함께
  전달해야 한다(영상 자체도 크롤링 적법성 6가지 기준을 별도로 강조).
- 노코드 크롤링 툴(옥토파스 등) 학습에 시간을 썼다가 포기한 학습자 대상 비교 사례로도
  유용 — "자연어 지시 한 줄 vs 노코드 툴의 규칙 설정" 차이를 보여줄 수 있다.
