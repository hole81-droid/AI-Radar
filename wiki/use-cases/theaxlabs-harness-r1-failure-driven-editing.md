> **공식**: Claude(Claude Code)로 실패 로그 분석 → 하네스 수정 → 재실행 검증 → 회귀 테스트
> 4단계 프롬프트 루틴을 매주 반복 실행 → 모델을 바꾸지 않고 에이전트 성공률을 개선
> (참고 논문 기준 +9.3%p)

## 무엇을 자동화했나

AX LABS 블로그가 소개한 **Harness-R1** 논문의 핵심 발견은 "모델 자체가 아니라 실행
환경(하네스)을 바꾸면 에이전트 성공률이 오른다"는 것 — 9B 소형 특화 모델이 하네스
최적화만으로 대형 LLM을 능가했다("검증 루프가 결과를 갈랐다"). 이 글은 이 발견을 GPU나
모델 재학습 없이, Claude Code에서 그대로 돌릴 수 있는 실무 루틴으로 번역한다.

## 어떻게 구성했나 (아키텍처)

- **개입 4지점**: 하네스를 고칠 수 있는 지점을 (1) 사전 브리핑(CLAUDE.md·시스템 프롬프트),
  (2) 단계별 체크리스트(실행 중 상태 힌트), (3) 실행 전 체크포인트(사전 검증),
  (4) 실행 후 오류 복구로 구분. 논문에서는 (3)·(4) — 실행 전후 개입 — 이 성능에 가장
  큰 영향을 미쳤다.
- **주간 루틴 (4단계 프롬프트)**:
  1. **실패 패턴 수집** — 로그에서 반복되는 실패를 추출·분류
  2. **수정안 설계** — 근본 원인을 겨냥한 좁고 재사용 가능한 개입안 생성
  3. **재실행 검증** — 기존에 실패했던 태스크를 새 설정으로 재실행해 확인
  4. **회귀 테스트** — 기존에 성공하던 태스크가 새 설정으로 깨지지 않는지 확인
- 이 루프는 GPU도 모델 재학습도 필요 없이 Claude 기반 로그 분석과 환경(CLAUDE.md·훅·
  체크리스트) 수정만으로 매주 반복 가능하도록 설계됐다.

## 벤치마크 데이터

| 항목 | 값 |
|---|---|
| 모델 | 미확인 (논문은 9B 특화 모델 사용, AX LABS의 Claude Code 적용판은 특정 모델 명시 없음) |
| 비용 | 미확인 — 다만 GPU·재학습 불필요가 핵심 셀링포인트 |
| 권한 설계 | 미확인 |
| 성숙도 | prototype — 논문 결과를 실무 루틴으로 번역한 프롬프트 템플릿 단계, Claude Code 적용 후 실측 사례는 없음 |

## 성과와 수치

- 참고 논문(Harness-R1) 수치: 3개 벤치마크 평균 성공률 44.3%→53.4%(+9.3%p) — **논문 자체의
  측정치**이지 이 워크플로를 Claude Code에 적용한 실측 결과가 아니다.
- AX LABS 글에는 이 루틴을 실제 적용한 조직의 도입 후 수치가 없다 — **claimed**로 분류.

## 재현 가이드 (난이도: 중)

1. 에이전트(Claude Code) 세션 로그·실패 사례를 주기적으로 수집하는 절차를 만든다.
2. 매주 위 4단계 프롬프트(수집→설계→검증→회귀)를 순서대로 실행하는 루틴을 설정한다
   (수동 실행 또는 `/schedule` 등 반복 작업 기능과 결합 가능).
3. 개입 지점을 4가지(사전 브리핑/체크리스트/사전 검증/사후 복구) 중 어디로 할지 실패
   유형별로 분류해 CLAUDE.md·훅·체크리스트 파일을 수정한다.
4. 수정 후 반드시 과거 실패 태스크 재실행 + 과거 성공 태스크 회귀 테스트를 함께 돌려
   "고쳤지만 다른 걸 깨뜨렸는지"를 확인한다.

## 강의·AX 활용 포인트

- "모델을 안 바꿔도 에이전트는 좋아질 수 있다"는 메시지는 AX 도입 초기 "최신 모델로
  업그레이드해야 하나"라는 오해를 바로잡는 데 유용한 반례다 — 하네스·프롬프트·검증
  루프 설계가 모델 선택보다 ROI가 클 수 있다는 근거로 인용 가능.
- [[loop-engineering]](루프 엔지니어링) 개념과 직접 연결된다 — "프롬프트 다음은 루프"라는
  기존 개념 페이지에 실무 4단계 템플릿 사례로 추가할 만하다.
- 정량 수치가 논문 것뿐이고 Claude Code 적용판 실측이 없다는 한계를 강의에서도 명확히
  구분해 전달해야 한다(참고 벤치마크 vs 실제 적용 성과 혼동 주의).
