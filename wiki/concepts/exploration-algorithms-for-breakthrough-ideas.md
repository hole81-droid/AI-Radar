# 탐색형 알고리즘 — AI가 아이디어를 좁히지 않게 하는 법

> **채택 근거**: MIT Sloan Management Review 2026-08-20. HN 무신호(해당 아웃렛
> 실측 게시 0건)이나 페이월 없이 전문 확인 가능했고 통제 실험 수치가 구체적이라
> 페이지화. 09-01·09-02 백필에서 Sloan을 저정독해 빠져 있던 항목.

## 문제 — "아이디어 버블"

효율을 위해 설계된 표준 알고리즘(검색·추천)은 이미 관련성이 높다고 판단한 것을
위로 올린다. 그 결과 조직은 **아이디어 버블(ideation bubble)** — 서로 비슷한
아이디어가 몰린 좁은 군집 — 에 갇힌다. AI를 아이디어 발상에 쓰면 발상이 넓어질
것 같지만, 도구가 **활용형(exploitation)**이면 오히려 좁아진다는 것이 요지다.

[[ai-innovation-human-bottleneck-framework]](HBR·HBS)가 "AI가 혁신 병목을 자동으로
풀어주지 않는다"고 진단했다면, 이 연구는 **그중 아이디어 생성 단계에서 무엇을
바꾸면 되는지**를 통제 실험으로 보여준다.

## 실험 수치

**실험실 연구 — 참가자 104명**
- 탐색형(exploration-based) 알고리즘으로 만든 아이디어가 표준 Google Search 대비
  **창의성 14% 상승**

**필드 연구 — 참가자 245명, 지속가능성 주제**
- 표준 Google Search 사용 시: 전문가가 초보자 대비 **통계적으로 유의한 우위 없음**
- 탐색형 알고리즘 사용 시: 전문가가 초보자를 유의하게 능가, 아이디어 창의성
  평균 **11% 상승**
- 탐색형 도구를 쓴 전문가의 아이디어는 **5개의 구분되는 군집**에 분포
  (다른 모든 조건은 1~2개 군집)

필드 연구의 첫 줄이 가장 중요하다 — **표준 검색을 쥐어주면 전문가와 초보자의 차이가
사라진다.** 도구가 전문성을 평준화해 버린 것이다. 탐색형 도구를 줬을 때에만
전문성이 다시 값을 한다.

## 관리자용 4가지 처방

1. **알고리즘 유형을 설계 변수로 다뤄라** — 돌파형 과제에 효율 중심 시스템을
   기본값으로 쓰지 말 것
2. **과제에 알고리즘을 맞춰라** — 정확도·베스트프랙티스 탐색에는 활용형,
   초기 발산적 아이디어에는 탐색형
3. **아이디어 포트폴리오를 감사하라** — 시맨틱 클러스터링으로 버블 형성을 진단하고,
   탐색형 도구를 쥔 전문가를 투입해 패턴을 깨라
4. **전문성에 투자하라** — 탐색형 도구와 짝지을 때 도메인 지식의 가치가 커진다

## 이 위키의 다른 발견과의 연결

[[multi-agent-hidden-profile-problem]]이 지적한 **LLM의 낮은 편차(low-variance)**와
같은 병의 다른 증상이다. 에이전트 30개가 브랜치 이름을 18개나 똑같이 짓는 현상과,
표준 검색이 전문가·초보자의 아이디어를 같은 군집으로 밀어 넣는 현상은 둘 다
"기본값이 수렴을 만든다"는 하나의 문제다. 처방도 같은 방향 — **다양성을 도구
설계 차원에서 강제로 넣어야 한다.**

## 강의·AX 활용 포인트

- **AX**: 사내 아이디에이션 워크숍·신사업 발굴에 AI를 넣을 때, "무슨 모델을 쓰나"보다
  "검색·추천 로직이 활용형인가 탐색형인가"를 먼저 묻게 하는 근거.
- **강의**: "AI를 쓰면 발상이 넓어진다"는 통념의 반례. +14%/+11%와 군집 5개 vs 1~2개는
  강의 슬라이드 한 장으로 정리된다.
- **한계**: 실명 기업은 비교 기준선인 Google Search뿐이고, 실험에 쓰인 탐색형 알고리즘의
  구체 구현은 원문에 특정되지 않았다. 상용 도구 추천이 아니라 **설계 원칙**으로 쓸 것.
