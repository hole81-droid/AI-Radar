# Citizen Development (시민 개발) — 현업이 AI로 직접 사내 도구를 만드는 흐름

## 무엇인가

개발자가 아닌 현업 담당자·경영자가 AI(코딩 에이전트, 노코드+LLM)로 자기 업무용
소프트웨어를 직접 만들어 쓰는 흐름. 개념 자체는 노코드 시대부터 있었지만, 2026년 들어
코딩 에이전트의 성능 향상으로 "간단한 자동화" 수준을 넘어 **회사 운영을 떠받치는 사내
도구**까지 현업이 만드는 단계로 올라왔다.

## 최근 근거 사례 (2026-06~07)

- [[varun-mayya-5-ai-apps-500-person-company]] — 창업자가 AI로 만든 앱 5개로 500명 규모
  회사의 콘텐츠 생산(영상 2,000개+)을 운영. "SaaS 구매 대신 자체 제작(build-not-buy)"의
  규모 상한을 끌어올린 사례.
- [[jocoding-ax-series-pwc-samil]] — 삼일PwC 등 국내 대기업이 "AI로 실무 문제를 푸는
  능력"을 채용 기준으로 삼기 시작 — 시민 개발 역량이 스펙을 대체하는 신호.
- [[gemini-spark-claude-cowork-routing]] — Claude Cowork처럼 파일 산출물을 만드는
  데스크톱 에이전트의 확산이 비개발자의 제작 진입장벽을 다시 한 단계 낮췄다.
- (2026-08-03) AWS와 바이브코딩 스타트업 Superblocks의 다년 계약 — AWS 고객의
  프라이빗 클라우드 안에 바이브코딩 툴을 내장해, 데이터를 외부로 보내지 않고도
  현업이 직접 업무 앱을 만들 수 있게 했다(Amazon Aurora·Bedrock 연동, AWS
  마켓플레이스 유통). "AI 코딩 에이전트(개발자용) 다음은 바이브코딩(현업용)"이라는
  2단계 물결론과 함께, 하이퍼스케일러가 특정 모델 종속 없이 "중립 플랫폼"으로
  포지셔닝하는 전략이 시민 개발의 엔터프라이즈 버전을 밀어주는 모양새다.
  [출처](https://techcrunch.com/2026/08/03/aws-is-helping-vibe-coding-startup-superblocks-and-the-implications-are-big/)

## 왜 중요한가

- 사내 도구의 경제학이 바뀐다: "요구사항 → IT 부서 → 백로그 6개월" 경로가
  "현업이 오후에 직접 제작"으로 단축. 기성 SaaS 대비 워크플로우 밀착도가 경쟁력이 된다.
- 반대급부로 거버넌스 문제가 따라온다 — 섀도우 IT, 보안·데이터 반출, 유지보수 주체 불명.
  AX 전략에서 "만들게 허용하되 등록·검토 체계를 두는" 균형 설계가 필수.

## 활용 포인트

- **강의**: 학습과정의 최종 목표 상(像)으로 제시 가능 — "도구 사용자"가 아니라
  "자기 업무의 도구 제작자". 수료 과제를 '내 업무용 앱 1개 제작'으로 설계.
- **AX**: 전사 확산 로드맵의 핵심 단계(파일럿 → 시민 개발자 양성 → 거버넌스 정착)를
  구성하는 개념 축.
