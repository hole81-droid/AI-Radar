# 시연용 모의 데이터 설계 방법론 — 심은 이야기 · 미끼 · 대조군

## 핵심 요약

에이전트 데모의 설득력은 모의 데이터의 설계 품질에 좌우된다. 아래 4원칙을 조합하면
"발견하는 순간"을 시연의 절정으로 만들 수 있다.

- **심은 이야기(발견될 이야기)**: 시연 데이터에 이상 신호·의도적 결함·문서 간 연결 서사를
  심어, 에이전트가 "발견"하는 순간이 시연의 절정이 되게 한다. (예: 생산일지의 야간조 불량
  급증 + 점검 메모의 원인 단서)
- **미끼(decoy)**: 일회성 스파이크 등 가짜 신호를 함께 심어, 에이전트가 지속성 기준으로
  진짜만 골라내는 판별력 자체를 볼거리로 만든다.
- **대조군**: 정상 사례(예: 건강한 거래처)를 나란히 두어 오탐이 아님을 증명한다.
- **재발견 검수**: 키트 생성 후 반드시 **새 세션에서 시연 프롬프트로 3회 재발견 테스트** —
  심은 이야기가 안정적으로 발견되는지 검증한 뒤에만 무대에 올린다.

## 활용 포인트

- **강의**: 부서별 실습 키트(생산/영업/재무/R&D 등 업무 영역별 가상 시나리오) 설계 시 표준
  체크리스트로 적용. "재발견 검수" 단계를 생략하면 라이브 데모에서 에이전트가 심은 이야기를
  못 찾는 리스크가 크다.
- 모의 데이터 설계는 도구·모델에 종속되지 않는 범용 교수 설계 기법이라 Claude Code 외
  다른 에이전트 데모에도 적용 가능하다.
