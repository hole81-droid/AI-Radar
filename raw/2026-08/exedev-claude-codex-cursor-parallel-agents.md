# Six months of writing code exclusively with agents

- 원문: https://blog.exe.dev/engineering-with-ai (HN: https://news.ycombinator.com/item?id=49465119, 68점)
- 수집일: 2026-08-29 (스캔), 게시일: 08-28 전후 추정(HN 등재 08-28)

## 요약 (WebFetch 종합)

exe.dev 블로그 저자가 6개월간 "직접 코드를 손으로 작성하지 않는다"는 개인 규칙을 세우고
Claude Code·Codex·Cursor·GPT-5.3·Opus 4.6을 병행 사용해 에이전트만으로 개발한 경험기.

### 워크플로우 아키텍처
1. 개인 규칙: "No more code by hand" — 에이전트가 작업을 완결해야 함(사람이 마무리 타이핑
   하지 않음).
2. 병렬 실행: 여러 에이전트를 exe.dev VM 각각에서 동시에 실행.
3. 오케스트레이션: 자체 개발 도구 `botd`가 VM 프로비저닝·에이전트 진행상황 추적·대화
   히스토리 보존을 담당.
4. 격리 전략: 에이전트마다 독립된 VM(bash 접근권)을 부여해 파일 충돌·자원 경합 방지.
5. 보안 경계: 외부 연동은 가능한 읽기전용으로 제한, 자격증명은 VM 내부 저장 대신
   프록시를 경유해 처리.
6. 검증 루프: 에이전트가 테스트 실행·CI 트리거·앱 구동·스크린샷 제공까지 담당해 사람은
   결과만 검토.

### 성과
- "경력을 통틀어 가장 많이 출시한 6개월"이라고 자평(정량 수치 없음).
- 피크 시점 동시 실행 VM 약 20개.
- 자체 개발한 오케스트레이션 도구 `botd`는 6개월 뒤 결국 폐기(더 나은 방식으로 대체 추정,
  구체 사유는 본문에 명시 안 됨).

### 핵심 통찰
"모델이 곧 루프의 역량을 결정한다(The model is what makes the loop capable)" — 개발자급
도구(셸 접근·컴파일러·브라우저)를 격리된 환경 안에서 에이전트에 쥐어주면 매 행동마다
승인을 받지 않고도 동작할 수 있고, 병목이 "실행 속도"에서 "아키텍처 의사결정"으로
옮겨간다는 것이 핵심 주장.
