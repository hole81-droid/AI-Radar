## WebFetch 정독 요약 (2026-09-30)

### Agensh란

Microsoft Research의 멀티 에이전트 프레임워크. 중앙 오케스트레이터가 작업을 배분하는 대신
공유 인프라를 통해 워커가 스스로 작업을 선택·진행상황 공유·결과 통합하도록 한다.

### 아키텍처 (오케스트레이터 없음)

- **공유 워크스페이스(Git 기반)**: 워커별 개별 브랜치, 덮어쓰기 방지 + 변경 이력·귀속 보존.
- **메시징 인터페이스(Mattermost 스타일)**: 공개 채널(낮은 우선순위 업데이트) + DM(긴급
  정보, 새 공유 컨텍스트 항목 등) — 워커가 끊임없이 방해받지 않도록.
- **공유 컨텍스트 보드**: append-only DB, 레코드 타입 5종(각 100자 제한, PATCH_SUMMARY만
  300자): OBSERVED(참조 행동)·FACT(검증된 발견)·FAIL(기각된 접근)·CLAIM(현재 작업 범위)·
  PATCH_SUMMARY(완료된 변경).

### 5단계 협업 루프

Gather(목표·동료 진행상황·보드 기록에서 컨텍스트 수집) → Claim(공유 컨텍스트로 하위작업
선점) → Act(도구 사용+발견사항 게시) → Verify(수락 기준 대조 검증) → Merge(요약과 함께
main에 병합, 충돌 시 해소). 모든 워커를 기다리게 하는 동기화 지점이 없어 진짜 병렬 실행
가능.

### 스케일링 결과 (ProgramBench — 바이너리만으로 프로그램 재구현, 인터넷 접근 없음)

- 단일 에이전트: 5개 과제 평균 19.31%
- 128 에이전트: 28.78% (+49% 상대개선)
- pandoc 단일: 33.89% → 55.06% (1,024 에이전트, +62% 상대개선)
- 시간: 128 에이전트가 pandoc 30% 도달까지 30분, 단일 에이전트는 2시간+

### Claude Code 적용 — 3단계 설계

**1단계(3~5 에이전트)**: 네이티브 Claude Code 에이전트 팀 + board.py 스크립트(공유
컨텍스트 레이어 추가). 훅 2종: TeammateIdle(마감 전 계속 작업, 15분 무응답 시 행동 촉구
또는 차단), TaskCompleted(검증 스크립트 실행, 테스트 실패 시 완료 차단).

**2단계(8~16 에이전트)**: 워커당 컨테이너(리포지토리 클론+공유 Git 업스트림+공유 볼륨
위 보드 파일). CLAIM 중복 감지로 충돌 해소, 나중 클레임자가 양보.

**3단계(32+ 에이전트)**: 완전한 Agensh 스택 — Gitea(PR/이슈), Mattermost(채널/DM), 보드
서비스, 워커별 내구성 큐를 갖춘 이벤트 라우터, 분산 워커 인프라(16노드×64워커 예시).

### 구체 구현

**board.py**: 파일 잠금 기반 append-only 보드 Python 스크립트. 타입별 조회·AND/OR grep
쿼리 지원. 호출 예: `python3 .team/board.py write FAIL "설명" --by 워커명`

**워커 프롬프트 템플릿**: 모든 워커에 동일(ID만 다름). 강조점: 방향을 묻지 말 것, 보드의
FAIL을 재시도하지 말 것, 병합 전 검증할 것, 5단계 루프를 무한 반복할 것.

**훅**: TeammateIdle(보드에서 최근 항목 확인, 15분 침묵 후 행동 촉구 또는 침묵 지속 차단),
TaskCompleted(검증 스크립트 실행, 테스트 미통과 시 완료 실패 처리).

### 전제조건

자동화된 검증기(레퍼런스 바이너리 또는 테스트 스위트), 병렬 하위작업으로 분해 가능한 작업,
속도가 중요한 시간 제약, 토큰 예산(비용이 에이전트 수에 선형 비례) 필요.
