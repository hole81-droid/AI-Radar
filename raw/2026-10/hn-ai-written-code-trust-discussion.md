# Ask HN: How to deal with shipping AI-written code you don't understand?

- URL: https://news.ycombinator.com/item?id=50151036
- 게시일: 2026-10-19
- 점수: 155
- 수집: WebFetch (HN Algolia items API)

## 핵심 내용

- 원문 질문(메타 개발자 제기): "이해하지 못한 AI 생성 코드를 어떻게 배포할
  것인가?"
- 긍정 사례: 항공우주 시뮬레이션 개발자 — "기능 설계 문서·구현계획·RCA 문서
  사전 검토"로 신뢰성 확보. 게임 개발자 — "E2E 테스트+다중 검증 체크".
- 부정 사례: 임베디드 개발자 — 클라우드 배포 중 "민감 자격증명·프로젝트 문서를
  공개 IP에 rsync"하는 실수.
- 제안된 해결책: 다중 LLM 교차검증(Claude로 코딩, Codex로 적대적 검토), 설계
  계약(Design by Contract), 퍼징/카오스엔지니어링/뮤테이션 테스팅, 상세 사양
  선행 작성, 핵심 로직만 엄격 리뷰.
- 커뮤니티 입장: 보수적("이해 없는 배포는 비전문적") 최다 지지, 현실적("테스트·
  E2E가 리뷰 대체 가능"), 회의적("속도 추구가 품질 훼손, 자동화 감시 필요").

## 수집 메모

- "도구 실사용 평가"로 분류 — 개발자들이 실제로 AI 코드 신뢰 문제를 어떻게
  다루는지 구체적 사례 기반 토론.
