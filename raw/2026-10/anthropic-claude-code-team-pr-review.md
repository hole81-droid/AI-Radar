# How the Claude Code team does code review

- 출처: https://claude.dev/blog/solving-code-review-at-anthropic/ (Anthropic 엔지니어링 블로그)
- 수집일: 2026-10-17 (HN 게시 2026-10-16, 136점)

## 요약 (WebFetch 정독)

### 문제
Claude Code 팀은 에이전트가 코드의 약 90%를 작성하게 되면서, 2026년 5월 일일 PR
2,500건 → 9월 30,000건 이상으로 폭증한 상황에서 전통적인 "한 줄씩 다 읽는" 인간
코드리뷰가 불가능해졌다. 인간의 주의력을 고가치 판단에 쓰기 위한 재설계가 필요했다.

### 핵심 메커니즘

**PR 생성 전 검증**
- 에이전트가 PR을 열기 전에 테스트·빌드·린터를 직접 실행
- 서브에이전트가 "신선한 컨텍스트"로 diff를 재검토
- 내부 Skill이 버그 탐색·코드 단순화를 수행

**자동 AI 리뷰 계층**
- 모든 PR에 Claude 기반 리뷰가 붙어 diff를 저장소 컨텍스트와 대조해 읽음
- 여러 에이전트가 병렬로 버그를 탐색하고, 별도 에이전트가 발견사항에 투표
- 검증된 발견사항만 심각도순으로 코멘트로 남음

**문서 기반 가이드**
- `CLAUDE.md`: 프로젝트 컨벤션·목표 명시
- `REVIEW.md`(코드 오너가 관리): 해당 영역에서 "실패"가 무엇인지 정의

**위험도 기반 인간 승인**
- 저위험(문서, 플래그): 인간 승인 0명
- 중위험(제품 변경): 1명
- 고위험(과금, 자동업데이터): 2명
- 신뢰된 작성자만 더 가벼운 승인 경로 접근

### 전체 워크플로 7단계
1. PR 생성 전 검증 + 에이전트 리뷰
2. 모든 PR에 AI 코드리뷰
3. 자동 보안 리뷰
4. 린트·타입·테스트·빌드 체크
5. 위험도별 인간 승인
6. 머지 큐 재검증
7. 피처 플래그·단계적 롤아웃·빠른 롤백

### 실측 수치 (2026년 6월~9월)
- 머지되는 PR 2배 이상 증가
- 되돌리기(revert)율 40% 이상 감소
- 실질 리뷰 코멘트를 받는 내부 PR 비율: 16% → 54%
- 1회 리뷰-수정 사이클 후 통과하는 PR: 65% → 78%
- 통과까지 평균 리뷰 라운드: 2.08 → 1.32

인간의 시간은 "모든 diff를 읽는 것"에서 "아키텍처 선택, 위험한 코드 소유권, 기능이
존재해야 하는지 여부" 같은 전략적 질문으로 이동했다.
